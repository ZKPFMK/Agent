Abstract
Tool-augmented large language model (LLM) agents aggregate dialogue
history, tool outputs, and retrieved content into an accumulated runtime
state to complete multi-step tasks. This execution model exposes agents to
indirect prompt injection (IPI) attacks, in which attacker-controlled
instructions embedded in external artifacts enter the agent state and
later influence tool use. Multi-turn IPI is especially
challenging because injected content can persist across intermediate
steps and trigger unauthorized state-changing actions only after it has
been merged with user intent in the same context.
This creates a source-attribution problem: existing
inference-time defenses can often detect suspicious behavior but do not
directly distinguish whether a pending action is supported by the user
task or influenced by injected content. Consequently, they resort to conservative
blocking, termination, or broad filtering, sacrificing utility for
security.
We propose AgentSentry, an inference-time defense that operationalizes
temporal causal diagnostics through boundary-local counterfactual
re-executions at tool-return boundaries. It substitutes the mediator under
a restored snapshot, records whether the pending proposal survives, and
aggregates user-view and probe scores across adjacent boundaries.
When a proposal is mediator-sensitive, AgentSentry purifies the
implicated mediator content while preserving task-relevant evidence and
resumes execution from the sanitized state.
We evaluate AgentSentry on AgentDojo across four task suites, three IPI
attack families, and three black-box LLM backbones. AgentSentry records
no observed successful attack in the evaluated cases (ASR=0%\mathrm{ASR}=0\%) and
achieves an average Utility Under Attack
(UA) of 76.10%76.10\%. Compared with the strongest evaluated baseline,
AgentSentry improves average UA by 1.841.84–7.607.60 percentage points,
with benign FPRs of 2.06%2.06\%–5.15%5.15\%. Additional evaluations examine
long-horizon and adaptive attacks, imperfect purification, runtime
overhead, and an OpenClaw engineering case study.
I Introduction
Tool-augmented large language model (LLM) agents increasingly execute multi-step tasks by combining model outputs with external tools, retrieval systems, and enterprise services [1, 2, 3, 4, 5].
During execution, the agent runtime accumulates dialogue history, intermediate tool outputs, retrieved passages, and memory into the context that guides subsequent planning and tool invocation [6, 7, 8].
This architecture enables long-horizon task completion, but it also expands the agent’s trust boundary by allowing external tool- or retrieval-returned content to enter the same context that later conditions model-generated actions.
Indirect prompt injection (IPI) exploits this tool-mediated context channel.
Rather than controlling the user prompt, an attacker embeds instructions in external artifacts such as emails, documents, webpages, calendar entries, or retrieved records.
When the agent later accesses these artifacts through legitimate tools or retrieval modules, attacker-written content can be incorporated into the execution context and treated as task-relevant evidence [9, 10, 11, 12].
A particularly difficult case is multi-turn IPI: the injected content may enter through an early read operation, persist across subsequent context updates, and only later influence a state-changing action at a write-capable boundary.
Figure 1 illustrates the multi-turn tool-mediated IPI path, where attacker-controlled content enters through an early tool read and can influence a later pending action after being accumulated into the agent context.
This threat is relevant to practical deployments.
Recent incidents and case studies indicate that artifact-mediated or tool-mediated prompt injection can affect systems that process external content through legitimate APIs, including a Microsoft 365 Copilot zero-click issue and code-interpreter-style data-exfiltration scenarios [13, 14, 15].
In many deployments, the application runtime can observe prompts, tool calls, tool returns, and pending actions, while the LLM backend remains a remote black box.
This setting makes application-layer inference-time defense a practical deployment point when model retraining, provider-side instrumentation, or access to internal model states is unavailable [10, 16, 17].
Fig. 1:
Representative multi-turn tool-mediated IPI attack path.
Existing inference-time defenses remain limited because they do not directly resolve the source of control behind a pending action.
Detection- and blocking-oriented defenses, such as trajectory re-execution and task-alignment guards, can flag suspicious behavior or prevent unsafe tool use, but typically respond by stopping execution or suppressing actions [16, 17].
Sanitization- and localization-based defenses reduce exposure to suspicious
content, but they do not by themselves determine whether a risky pending
proposal is mediator-sensitive under controlled substitution, nor do they
re-derive a supported continuation once such sensitivity has been
identified [18, 19, 20, 21, 22].
The resulting security–utility tension is not merely an efficiency issue: strong protection is often obtained by terminating, rolling back, or over-constraining otherwise benign multi-step workflows.
Our key observation is that multi-turn IPI creates a
source-attribution problem at action time.
After external content has been incorporated into the agent state,
the same pending action may admit competing explanations.
For example, sending an email may be a legitimate continuation of
the user’s request, or it may depend on an instruction embedded in
a retrieved document.
Purely observational methods, such as lexical detectors,
action-level alignment checks, and trajectory-level similarity
tests, can flag suspicious behavior, but they do not directly
establish which source the pending action depends on.
This makes the core security question interventional at the runtime
boundary:
would the same pending action still be proposed if the implicated
mediator content were locally purified while the user view and the
remaining boundary state were held fixed?
To address these challenges, we propose AgentSentry, an
inference-time defense framework for tool-augmented LLM agents.
AgentSentry adopts an execution-level temporal attribution
takeover abstraction: attacker influence need not manifest as an
immediate abnormal action, but may persist through tool- and
retrieval-mediated state updates and later make a consequential
proposal sensitive to mediator content at a write-capable boundary.
AgentSentry operationalizes this idea through a diagnose-and-continue pipeline.
At each tool-return boundary, it restores the boundary snapshot and performs
side-effect-free counterfactual re-executions that substitute the user view
and/or mediator content while holding the restored state, tool set, and
decoding configuration fixed.
The user-preserving mediator-purification contrast serves as the primary
live-policy signal, the probe-conditional contrast provides corroborating
evidence, and the user-view and probe trends are aggregated over a short
window of adjacent boundaries so that a progressive shift toward
mediator-supported behavior need not be decisive at any single one.
When these signals identify a pending proposal as mediator-sensitive,
AgentSentry purifies the implicated content, removing instruction-bearing
control signals while preserving task-relevant evidence, then revises the
pending action under the sanitized state and permits only authorized,
evidence-supported effects, so the agent continues the original workflow
rather than terminating execution or broadly suppressing tool use.
We evaluate AgentSentry on the AgentDojo
benchmark [10] across four task suites, three IPI
attack families, and three black-box LLM backbones, where it records zero
observed successful attacks (ASR=0%\mathrm{ASR}=0\%) and an average
Utility Under Attack (UA) of 76.10%76.10\%.
Against the strongest evaluated baseline on each backbone, this improves
average UA by 1.841.84–7.607.60 percentage points and reduces a residual
average ASR of 1.54%1.54\%–7.26%7.26\% to zero observed successes, with benign
FPRs of 2.06%2.06\%–5.15%5.15\%.
Additional evaluations examine long-horizon and adaptive attacks, imperfect
purification, threshold sensitivity, representative failures, and attacked-
and benign-path overhead, together with an OpenClaw engineering case
study [23, 24].

II Related Work
II-A Tool-Augmented LLM Agents and Indirect Prompt Injection
Modern LLM agents increasingly interact with external tools, retrieval systems, and mutable environments to complete real-world tasks.
Early agent frameworks relied on manually specified tool interfaces [3, 2], while later work showed that tool-use behavior can also be acquired from demonstrations or synthetic supervision [1, 25, 8, 26].
Commercial systems further expose unified multi-tool and multi-modal capabilities [27].
This tool-augmented setting also introduces a distinct attack surface.
When agents ingest heterogeneous and partially untrusted artifacts such as emails, documents, or web pages, adversarial instructions embedded in these artifacts may be incorporated into the evolving context and subsequently affect downstream planning and tool use.
This threat is commonly referred to as indirect prompt injection (IPI) [9].
Benchmarks such as InjecAgent [28] and AgentDojo [10] formalize this setting in multi-step, multi-tool environments, showing that injected external content can trigger unsafe behavior under benign user requests.
II-B IPI Attacks
Existing IPI attacks broadly fall into two categories.
The first targets general weaknesses in instruction following and prompt boundary separation.
Representative examples include reusable injection templates, control-token patterns, and explicit instruction overrides that cause the model to ignore prior context or safety constraints [29, 30, 31, 32, 33, 34, 35].
The second category exploits the structure of specific agent environments.
Web agents are vulnerable to environmental and context-based injections that manipulate perception and action routines [36, 37, 28].
Computer-use agents can be affected by adversarial interface patterns [38], while multimodal agents can be influenced by visually embedded prompts [39].
These attacks do not require control of the user prompt; instead, they operate through external content channels that the agent later treats as task-relevant context [40].
II-C Inference-Time Defenses
Defenses against prompt injection can be broadly grouped into training-time and inference-time approaches.
Training-time methods improve robustness through adversarial fine-tuning or related optimization procedures [41, 42, 43], or train dedicated detectors for suspicious inputs and traces [44].
While effective in some settings, these methods often require model access and substantial retraining costs, limiting their applicability to deployed black-box agents.
Inference-time defenses instead operate at runtime.
Prompt-level methods separate or annotate untrusted content using delimiters, authentication tags, or known-answer detection prompts [45, 46, 31].
Tool-policy defenses constrain tool use through allowlists or task-specific control policies [10, 47].
IPIGuard [48] extends this line of defense by
constructing a tool-dependency graph to constrain
injection-induced tool-use paths.
Sanitization and localization defenses, including PromptArmor [18], DataFilter [19], Soft Instruction De-escalation Defense [20], CommandSans [21], and PromptLocate [22], suppress, rewrite, or localize instruction-bearing content before it influences downstream behavior.
Agent-level and runtime-trace guards provide another runtime
defense family.
MELON [16] uses masked re-execution to detect trajectory inconsistencies, while Task Shield [17] checks whether proposed actions align with the user objective.
AgentSentinel [7] targets computer-use
agents by intercepting sensitive operations and auditing
execution traces.
AgentArmor [49] applies program analysis
to agent runtime traces to enforce execution-time constraints
against prompt injection, while
TraceAegis [50] combines hierarchical trace
analysis with behavioral anomaly detection.
These systems provide useful runtime protection signals through
action checking, trace analysis, and anomaly detection, but
commonly respond by rejecting, constraining, or terminating
suspicious execution paths.
In multi-turn IPI, this can prevent attacks but may also truncate benign workflows once ambiguity arises.
II-D Attribution- and Provenance-Based Defenses
Within the broader family of inference-time defenses, recent work
has begun to use attribution and provenance signals to identify
which context source influences agent behavior.
CausalArmor [51] uses causal ablation to
estimate the influence of untrusted context segments and sanitizes
segments that exert disproportionate control over agent behavior.
AttriGuard [52] performs action-level attribution for each
proposed tool invocation independently, re-executing the agent under a
control-attenuated view of external observations.
ProvSEEK [53] uses LLM-driven
provenance forensics to support threat investigation and
detection.
Unlike these approaches, AgentSentry holds the observed user view fixed and
substitutes only the mediator, so the resulting contrast is referenced to the
pending proposal itself rather than to an ablated context segment or to a
probe-induced action. It additionally tracks the user-view and
probe-conditional scores across a short window and reuses the same projection as the repair applied to the live state,
allowing the original workflow to continue under a repaired boundary state.
Our focus is therefore boundary-level attribution with safe continuation,
rather than segment-level sanitization, action-level attribution, or
provenance-oriented forensic analysis alone.
III Problem Setting
III-A Agent Model and Execution Semantics
We formalize a tool-augmented LLM agent as a composable state transformer operating over an
internal task context and an external environment.
Let 𝒞\mathcal{C} denote the internal state space representing the agent context, including the dialogue history, intermediate reasoning artifacts, tool outputs, retrieval snippets, and persistent memory.
Let 𝒜\mathcal{A} denote the action space, where an action may contain a natural-language response and a (possibly empty) sequence of tool calls with arguments.
Let 𝒪\mathcal{O} denote the external environment state space (e.g., inbox, calendar, file system, and third-party services) that can be queried and modified by tool executions.
Context-to-action policy.
The LLM is modeled as a context-to-action transformer

III-B Deployment Setting and Threat Model
We consider a tool-augmented LLM agent whose application runtime executes
locally while next-step generation is obtained from a remote black-box LLM API.
The runtime maintains the dialogue state, serializes model inputs, dispatches
tool and retrieval calls, stores intermediate results, and commits externally
visible side effects.
As illustrated in Figure 1, our goal is to
defend this application-layer pipeline against IPI under this black-box
setting.
Trust boundary.
We trust the local runtime, including the system prompt, tool wrappers,
authorization logic, deployment policy, and the snapshot-and-restore mechanism
used by the defense.
We do not trust externally sourced content once it enters the workflow,
even when returned through legitimate tools; emails, webpages, retrieved
passages, shared documents, database records, and persistent notes originating
outside the runtime are all treated as untrusted.
The remote LLM is likewise a black box: the defender may query it, but cannot
inspect or modify model parameters, hidden states, or provider-side safeguards.
Attacker capability.
The attacker cannot control the user request, the local runtime, the system
prompt, the tool schema, or the model provider, but can inject malicious text
into external content channels the agent may later access, for instance by
sending an email, publishing a webpage, editing a shared document or calendar
entry, inserting a database record, or poisoning a persistent note.
The attack proceeds indirectly: attacker-authored content is
returned through normal tool use, retrieval, or memory recall, serialized into
the agent context, and may influence later reasoning and action selection.
Attack goal and success criterion.
The attacker aims to induce an unauthorized high-impact action that
violates user intent or deployment policy, such as exfiltrating private data,
sending an unauthorized message, or performing a destructive state change.
An attack succeeds only if such an action is committed to the external
environment.
We additionally record whether the undefended agent proposes such an
action, since without an application-layer safeguard the runtime would normally
execute it.
Defender scope.
The defender operates at the application layer and controls the local runtime.
It may cache and restore tool-return boundaries, reuse recorded tool or
retrieval returns, perform side-effect-free re-executions, substitute a
sanitized mediator view, revise a pending action, and withhold an unresolved
external effect. The defender does not require model parameters, hidden states,
gradients, fine-tuning, or provider-side modifications.
Out of scope.
We exclude direct malicious user prompts, compromised local runtimes or tool executors, malicious tool schemas, operating-system or network compromise, and collusion by the model provider.
III-C Source-Attribution Problem
The threat model above induces a boundary-local source-attribution problem. At a
tool-return boundary bb, newly returned tool, retrieval, or memory content has
entered the agent context before the next action is committed. We write the
model-visible boundary context as
cb=hb⊕xb⊕rb,c_{b}=h_{b}\oplus x_{b}\oplus r_{b},
(4)
where hbh_{b} denotes the restored non-target runtime state held fixed across
controlled re-execution regimes, xbx_{b} is the runtime-addressable user view, rbr_{b} is the
runtime-addressable mediator view, and ⊕\oplus denotes runtime serialization.
The replayable boundary snapshot is sb=(hb,xb,rb)s_{b}=(h_{b},x_{b},r_{b}).
Given sbs_{b}, a pending action aba_{b}, the trusted user goal gg, and deployment
policy Π\Pi, the defender must determine whether the pending behavior remains
supported by the user task or is sensitive to mediator content. The same action
may be a legitimate continuation of the user request or may have been induced
by an external artifact, so content screening alone is insufficient.
IV Design of AgentSentry
AgentSentry is an inference-time defense for tool-augmented LLM agents. It
operates on the live execution trajectory and intervenes at tool-return
boundaries, after mediator content has entered the local context and before the
next action is committed. Figure 2 presents the
pipeline. AgentSentry first performs boundary-local attribution diagnosis and then
applies context purification and action revision to continue execution under a
sanitized state.
Fig. 2: AgentSentry pipeline for defending against multi-turn IPI.
IV-A Design Overview
AgentSentry implements the attribution problem in
Section III-C as a two-stage runtime defense.
All diagnostic executions are side-effect-free: replayed tool calls are not
executed, and replayed external effects are never committed.
Stage 1: Boundary-local diagnosis.
AgentSentry restores the boundary snapshot and evaluates the pending behavior
under four controlled re-execution regimes. The regimes hold the restored non-target state fixed
while varying the user-channel input and mediator view. Their outcomes are
summarized by replay-based attribution scores. AgentSentry aggregates these contrasts over a short execution window to capture both abrupt and gradually emerging takeover.
Stage 2: Purified continuation.
When takeover is detected, AgentSentry does not roll back the full trajectory or disable tool use. Instead,
it purifies the implicated mediator content, revises the pending action under
the repaired boundary state, and continues the original workflow when a
supported continuation remains available. Externally visible effects are
validated before commitment.

IV-C Stage 1: Boundary Instrumentation and Replay Operators
At each boundary bb, AgentSentry stores a replayable snapshot of the local
runtime state, and the replay cache reuses the same tool, retrieval, or memory
return across regimes without re-querying the external environment.
All replay executions run in dry-run mode: the model may propose tool
calls, but none is executed and no external effect is committed.
Two operators act at the boundary, a masking operator on the user
channel and a purification operator on the mediator channel.
Masking operator.
Inside replay, the masking operator replaces the runtime-addressable user view
xbx_{b} with a fixed masking probe xbmaskx_{b}^{\mathrm{mask}}, preserving
the restored state, tool availability, mediator realization, and decoding
configuration.
The probe asks whether the visible tool, retrieval, or memory content attempts
to govern the agent and, when applicable, returns complete verbatim control
evidence together with a probe-induced candidate action.
Ordinary procedures or factual parameter claims are not treated as control
solely because they mention a possible action.
Audit records produced under the probe serve dry-run diagnosis only and never
enter the live trajectory.
Purification operator.
Control-bearing spans reported in the audit records produced under the masking
probe are aligned to the cached mediator and collected in a grounded evidence
set 𝒢b\mathcal{G}_{b}. AgentSentry then constructs
rb(san)≜𝖯𝗎𝗋𝗂𝖿𝗒⁡(rb,𝒢b).r_{b}^{(\mathrm{san})}\triangleq\mathsf{Purify}(r_{b};\mathcal{G}_{b}).
(8)
The operator performs deterministic span alignment, range merging, and
schema-preserving projection. Content outside the selected ranges is retained.

IV-E Stage 1: Replay-Based Attribution Scores
At a fixed tool-return boundary bb, AgentSentry computes four replay-based
attribution scores:
SbU\displaystyle S_{b}^{U}
=p^borig​(ab)−p^bmask​(ab),\displaystyle=\widehat{p}_{b}^{\texttt{orig}}(a_{b})-\widehat{p}_{b}^{\texttt{mask}}(a_{b}),
(11)
SbM\displaystyle S_{b}^{M}
=p^bmask​(abmask)−p^bmask_sanitized​(abmask),\displaystyle=\widehat{p}_{b}^{\texttt{mask}}(a_{b}^{\mathrm{mask}})-\widehat{p}_{b}^{\texttt{mask\_sanitized}}(a_{b}^{\mathrm{mask}}),
(12)
SbR\displaystyle S_{b}^{R}
=p^borig_sanitized​(ab)−p^bmask_sanitized​(ab),\displaystyle=\widehat{p}_{b}^{\texttt{orig\_sanitized}}(a_{b})-\widehat{p}_{b}^{\texttt{mask\_sanitized}}(a_{b}),
(13)
SbL\displaystyle S_{b}^{L}
=p^borig​(ab)−p^borig_sanitized​(ab).\displaystyle=\widehat{p}_{b}^{\texttt{orig}}(a_{b})-\widehat{p}_{b}^{\texttt{orig\_sanitized}}(a_{b}).
(14)
SbUS_{b}^{U} is the observed-mediator user-view substitution score, indicating
whether the pending proposal is no longer reproduced once the observed user
view is replaced by the masking probe, and SbMS_{b}^{M} is the probe-conditional
mediator-purification score,
indicating whether the selected spans account for the probe-induced action.
SbRS_{b}^{R} is its sanitized-mediator counterpart, indicating whether the same
proposal remains user-anchored once the implicated content is removed, while
SbLS_{b}^{L} is the user-preserving mediator-purification score: both of its
regimes retain the observed user view, so it indicates whether the pending
proposal survives that removal under the user’s own request.
The takeover decision uses SbLS_{b}^{L} and SbMS_{b}^{M} at the current boundary and
the trends of SbUS_{b}^{U} and SbMS_{b}^{M} across the window, with SbRS_{b}^{R}
retained for trace-level analysis; whether a purified continuation is admitted
is determined in Stage 2.
IV-F Stage 1: Takeover Detection
A boundary is applicable to the local replay test when the original proposal is
nonempty, a control-positive probe-induced action is available so that
SbMS_{b}^{M} is defined, and the required sanitized comparisons are executable.
At all other boundaries we set SbU=SbM=SbL=0S_{b}^{U}=S_{b}^{M}=S_{b}^{L}=0 and Lb=0L_{b}=0 as a
zero-fill convention.
Boundary-local attribution.
At an applicable boundary, AgentSentry defines
Lb=𝕀[SbL>δL∧SbM>δM].L_{b}=\mathbb{I}\!\left[S_{b}^{L}>\delta_{L}\land S_{b}^{M}>\delta_{M}\right].
(15)
The gate requires both user-preserving mediator sensitivity of the pending
proposal and corroborating probe evidence; the masked comparison alone cannot
establish takeover.
Temporal aggregation.
The local gate is referenced to the pending proposal and therefore remains
silent while mediator influence is present but not yet acted upon.
To capture a progressive shift from user-supported to mediator-supported
behavior, AgentSentry retains the attribution scores over the sliding window
Wb={max⁡(1,b−w+1),…,b}W_{b}=\{\max(1,b-w+1),\ldots,b\} and forms the histories
𝐬bU=(SuU)u∈Wb,𝐬bM=(SuM)u∈Wb.\mathbf{s}_{b}^{U}=\bigl(S_{u}^{U}\bigr)_{u\in W_{b}},\qquad\mathbf{s}_{b}^{M}=\bigl(S_{u}^{M}\bigr)_{u\in W_{b}}.
(16)
Ordinary least-squares fitting yields
βbU=slope⁡(𝐬bU),βbM=slope⁡(𝐬bM),\beta_{b}^{U}=\operatorname{slope}(\mathbf{s}_{b}^{U}),\qquad\beta_{b}^{M}=\operatorname{slope}(\mathbf{s}_{b}^{M}),
(17)
evaluated only when |Wb|=w|W_{b}|=w; before a complete window is available we set
βbU=βbM=0\beta_{b}^{U}=\beta_{b}^{M}=0. A negative βbU\beta_{b}^{U} indicates weakening
user-view anchoring, whereas a positive βbM\beta_{b}^{M} indicates increasing
probe-conditional mediator dependence. The temporal replay risk is
ℛb=12​([−βbU]++[βbM]+),[v]+≜max⁡{v,0}.\mathcal{R}_{b}=\frac{1}{2}\left(\left[-\beta_{b}^{U}\right]_{+}+\left[\beta_{b}^{M}\right]_{+}\right),\qquad[v]_{+}\triangleq\max\{v,0\}.
(18)
Because a declining user-view score alone does not establish mediator control,
the temporal branch additionally requires
HbM=𝕀[maxu∈WbSuM>δM]H_{b}^{M}=\mathbb{I}[\max_{u\in W_{b}}S_{u}^{M}>\delta_{M}].
Delayed action realization.
Let MbM_{b} denote the delayed-match indicator defined in
Appendix B, which records whether the current
pending action structurally matches a recent control-positive,
purification-sensitive, and consequential probe-induced action. The
replay-attributed takeover indicator is
𝖳𝖺𝗄𝖾𝗈𝗏𝖾𝗋b=𝕀[Lb=1∨(ℛb≥γ∧HbM=1)∨Mb=1].\mathsf{Takeover}_{b}=\mathbb{I}\!\left[L_{b}=1\lor\left(\mathcal{R}_{b}\geq\gamma\land H_{b}^{M}=1\right)\lor M_{b}=1\right].
(19)
The first clause captures an abrupt boundary-local takeover, the second a
progressive user-to-mediator shift across recent boundaries, even where no
single boundary satisfies the local gate, and the third delayed realization of
a previously attributed control action.
The reported configuration uses w=3w=3 and a configured replay budget K=1K=1,
with deterministic replays collapsed to one effective outcome per regime. The
decision parameters are
(δL,δM,γ)=(0, 0, 0.25).(\delta_{L},\delta_{M},\gamma)=\left(0,\,0,\,0.25\right).
(20)
Here δL\delta_{L} and δM\delta_{M} are the minimum positive attribution contrasts
and γ\gamma is the temporal alarm threshold; with binary scores over a
three-boundary window, γ=0.25\gamma=0.25 is attained by a maximal change in either
trend. With zero-filled inapplicable boundaries, this clause also fires at the
first post-warm-up boundary with SbM>δMS_{b}^{M}>\delta_{M}, even if SbL=0S_{b}^{L}=0
(Appendix D). Window warm-up and sensitivity are
described in Appendix A-C.

mediator view and re-derives the pending continuation under the sanitized state.

and derives the revised proposal
a~b=𝖱𝖾𝗏𝗂𝗌𝖾⁡(ab(san),g,Π,cb(san)).\widetilde{a}_{b}=\mathsf{Revise}\left(a_{b}^{(\mathrm{san})};g,\Pi,c_{b}^{(\mathrm{san})}\right).

V Evaluation
We evaluate AgentSentry primarily on the AgentDojo
benchmark [10], which provides controlled multi-hop
tool execution, structured external feedback, and adversarial context
perturbations.
Unlike evaluations that examine single-turn prompt
manipulations [31, 28], we focus on
settings where external signals accumulate across turns and influence tool
selection in later stages.
We further report an OpenClaw engineering case
study [23, 24] covering calendar, drive,
email, filesystem, and web workflows in a deployed-style local-agent setting.
V-A Experimental Setup
Model Selection.
We evaluate three black-box backbones spanning different capability levels and
design ecosystems: GPT-4o, a high-capability model widely adopted in
recent agent benchmarks [10];
GPT-3.5-turbo, a less capable but widely deployed model; and
Qwen3-Max, a strong model from an alternative training and alignment
ecosystem.
All are accessed strictly as black boxes and receive identical system prompts,
tool interfaces, and environments.
Datasets and Tasks.
All experiments use the four standard AgentDojo suites, Travel,
Workspace, Banking, and
Slack [10], which cover itinerary
construction, document and file manipulation, constrained transactional
workflows, and multi-party communication.
Each instance induces a sequence of tool invocations that combine intermediate
outputs with evolving conversational context, so external content can
influence later decisions.
We adopt the latest public release (v0.1.35), in which the Workspace suite
expands from 66 to 1414 injection tasks and the total number of security test
cases increases from 629629 to 949949.
AgentDojo records turn-level traces of model messages, tool calls and
arguments, return values, and state transitions, which supply the mediator
variables required for controlled re-execution.
Attack Types.
We evaluate three IPI families that manipulate contextual signals returned by
external tools.
Important Instructions [10] injects
authority- or urgency-marked directives into free-text tool returns, framed as
mandatory preliminary steps.
Tool Knowledge [10] embeds
documentation-style guidance, including tool names and argument
specifications, biasing the agent toward a particular invocation or parameter
choice.
InjecAgent [28] inserts concise imperative
overrides into structured metadata fields ordinarily treated as factual
records.
OpenClaw engineering case study.
Beyond AgentDojo, we conduct a surface-balanced case study on OpenClaw, a
representative local-agent platform for end-to-end security
evaluation [23, 24].
It is not a second aggregate benchmark; it documents the implementation and
selectivity of AgentSentry’s boundary instrumentation.
Across five surfaces, we instantiate attacked workflows with weak and strong
injected artifacts together with matched benign workflows over the same tools,
and report takeover and benign alarms in
Section V-G.
Defense Mechanisms.
We use No Defense as the undefended reference and compare AgentSentry
against representative inference-time defenses in five categories, all
evaluated under identical task suites, attack configurations, tool interfaces,
and backbone settings.
Model-based detection is represented by a DeBERTa-v3 classifier applied
to tool-returned content [44].
Prompt-level augmentation includes
Delimiting [45], which marks external
content with explicit textual boundaries, and Repeat
Prompt [54], which restates the user objective
around the incorporated context.
Tool-policy and dependency constraints include Tool
Filter [10], an invocation allowlist, and
IPIGuard [48], which constrains execution through a
tool-dependency graph.
Agent-level and runtime-trace guards include MELON and
MELON-Aug [16], based on masked trajectory
re-execution; Task Shield [17], which blocks steps
misaligned with the user objective; AgentArmor [49],
which applies program analysis to runtime traces; and
TraceAegis [50], which combines hierarchical trace
analysis with anomaly detection.
Attribution- and provenance-based defenses include
CausalArmor [51], which ablates and sanitizes
untrusted context segments; AttriGuard [52], which
attributes each proposed invocation independently under a control-attenuated
view of external observations; and ProvSEEK [53],
which performs LLM-driven provenance forensics.
Collectively, these baselines form a representative comparison
set for assessing AgentSentry’s security–utility trade-off.
Evaluation Metrics.
We evaluate security and task performance using four metrics summarized in
Table I: Attack Success Rate (ASR, ↓\downarrow), Utility Under Attack (UA, ↑\uparrow),
Clean Utility (CU, ↑\uparrow), and False Positive Rate (FPR, ↓\downarrow).
In addition, to characterize AgentSentry’s deployment cost, we
measure attacked- and benign-path end-to-end latency, total model
calls, and token consumption on benchmark-scale AgentDojo workflows.

Research Questions.
We evaluate AgentSentry by addressing:
•
RQ1: How effective is AgentSentry at mitigating multi-turn IPI across attack families and black-box LLM backbones, as quantified by the ASR–UA trade-off?
•
RQ2: Which attribution components are necessary to attain the observed security–utility frontier (ablation)?
•
RQ3: Are takeover alarms mechanistically interpretable and temporally well-localized at tool-return boundaries?
•
RQ4: Does AgentSentry remain effective under delayed, memory-propagated, and distributed injections, and under adaptive attacks?
•
RQ5: What latency, call, and token cost does AgentSentry
incur on attacked and benign executions?
We additionally report an OpenClaw engineering case study, which uses a
distinct local-agent harness and reports workflow-level alarm counts rather
than benchmark-defined task utility.

Why temporal attribution diagnostics improve
the trade-off.
The comparison shows that the security–utility
trade-off depends not only on whether a defense performs
attribution, but also on the unit of diagnosis and how the
resulting evidence is translated into mitigation.
Prompt- and content-level defenses filter external evidence,
whereas tool-policy, dependency-, and trajectory-level defenses
constrain the actions that may follow.
These interventions can suppress attacks, but may also remove
task-relevant evidence or truncate legitimate multi-step
execution.
Attribution-oriented defenses localize suspicious influence more
directly and therefore preserve greater utility.
CausalArmor attributes influence to untrusted context segments,
whereas AttriGuard attributes individual proposed tool
invocations.
However, identifying an influential segment or invocation does
not by itself ensure that the implicated influence can be removed
while preserving a valid continuation of the original task.
This distinction is reflected in their remaining ASR and FPR in
Table II.
AgentSentry performs attribution diagnosis at the tool-return boundary
where untrusted mediator content enters the execution state.
Its controlled contrasts assess both whether the pending behavior
is sensitive to the unsanitized mediator and whether task-consistent
continuation remains recoverable after purification.
AgentSentry then applies the same localized mediator
transformation during mitigation and re-derives the pending action
under the sanitized state.
This alignment of diagnosis, localized repair, and continued
execution preserves task-relevant evidence while suppressing the
control-bearing influence associated with the pending deviation.
The observed combination of zero successful attacks, high average
UA, and low benign FPR is consistent with the selectivity of this
diagnose-and-continue design.

V-E Long-Horizon Scalability and Targeted Robustness (RQ4)
The standard AgentDojo evaluation is dominated by short attack
horizons and by attack constructions that are not tailored to the
defense.
We therefore conduct three complementary stress evaluations with
separate protocols and denominators.
Long-horizon injection.
The suite crosses two dimensions: the propagation family, being
delayed trigger, persistent-memory poisoning, or distributed
accumulation, and the attack surface, being argument-level
recipient manipulation or scope-level silent over-collection.
Each family is evaluated at L∈{3,6,12,24}L\in\{3,6,12,24\} with four workflows
per surface in every cell, giving 96 attacked workflows and 96
matched benign controls.
AgentSentry prevents 85 of the 96 injected objectives, an ASR of
11.46%11.46\% and a UA of 88.54%88.54\%, and intervenes on 9 of 96 benign
controls.
Protection is strongest at short horizons and degrades as source
evidence must survive longer intervals, memory transitions, and
multi-source composition.
Among baselines with non-zero utility, CausalArmor is the strongest at
37 successful attacks and AttriGuard reaches 71; MELON records 32 only
by withholding the requested send, and thus zero strict utility.
The two surfaces exercise different parts of the decision rule.
Argument-level manipulation typically changes the complete endpoint–argument signature at the final effectful boundary, so the user-preserving boundary-local contrast supplies most of the protection on this evaluated surface.
Scope-level over-collection preserves the authorized send endpoint
and recipient while altering the provenance of the message body
through earlier out-of-scope reads, and the deviation appears only
as a trend across adjacent boundaries.
Disabling temporal aggregation accordingly raises scope-level ASR
from 7/48 to 43/48, close to the undefended rate, while changing
argument-level ASR by a single workflow.
The temporal clause is thus redundant where a boundary-local
contrast already exposes the deviation, and load-bearing where it
does not.
Mechanism-targeted adaptive attacks.
The adaptive study holds workflow length fixed and instead varies
the attack construction against the replay, purification,
provenance, and commitment mechanisms, since adaptive attacks are known to
break IPI defenses [55].
Of 36 transformations, 19 activate in their same-case undefended
controls.
AgentSentry prevents 17 of these, raises an alarm in 18, and
localizes 17 within one boundary.
Every activated trigger-position, cross-return, and probe-aware
transformation is blocked; both survivors are
factual-recipient-poisoning cases, in which the mediator supplies an
effect-bearing argument as plausible metadata rather than as
instruction-bearing control.
Replay tests dependence on grounded control spans but does not
adjudicate the truth of a plausible field value, which delimits the
scope of instruction-oriented purification. Appendix E details each transformation.
Operator and threshold sensitivity.
We further vary the configuration choices the defense itself
controls.
Applying purification at every boundary for which the masking probe
produces a control-positive audit record reaches comparable attack survival but intervenes on
21 of 36 benign controls against 6 of 36 under the deployed
configuration: attribution does not strengthen purification; it makes
purification selective.
Projection width matters independently, since halving each grounded
span raises attack survival from 2/19 to 6/19 while leaving benign
intervention unchanged.
Stripping the enclosing markup from the injected artifacts leaves
conditional attack survival essentially unchanged, at two of 17
activated cases against two of 19, so the operator is keyed to
grounded control spans rather than to a fixed delimiter.
Raising (δL,δM,γ)(\delta_{L},\delta_{M},\gamma) raises attack survival from
2/19 to 5/19 as the temporal clause is disabled, and crossing the
attribution boundary suppresses intervention entirely.
Four practical limits of the deployed configuration remain: residual
attacker state outside the sanitized mediator view, projection of
procedural evidence a benign task depends on, factual parameter
poisoning, and over-sanitization when malicious and task-supporting
content share a span.

The overhead of AgentSentry is of the same order as that of other defenses

The four controlled re-execution regimes specify the logical attribution

VI Conclusion
We propose AgentSentry, an application-layer inference-time defense
against indirect prompt injection in tool-augmented LLM agents.
AgentSentry performs boundary-local counterfactual replay at
tool-return boundaries to determine whether a pending structural
proposal is sensitive to grounded mediator content.
When the takeover rule is satisfied, it purifies the implicated
content and resumes execution under a sanitized state rather than
terminating the workflow. On AgentDojo, across four task suites, three IPI families, and
three black-box LLM backbones, AgentSentry records zero observed
successful attacks and achieves an average UA of 76.10%76.10\%,
improving UA by 1.841.84 to 7.607.60 percentage points over the
strongest evaluated baseline while reducing its residual average
ASR of 1.54%1.54\% to 7.26%7.26\% to zero observed successes.
Dedicated stress suites delimit this result: ASR is 11.46%11.46\% on
long-horizon workflows, where protection depends on source evidence
remaining groundable across extended injection-to-effect intervals,
and conditional attack survival is 10.53%10.53\% under
mechanism-targeted adaptive attacks, where the
residual cases are confined to factual parameter poisoning.
An OpenClaw engineering case study additionally documents the trace-level behavior of the boundary instrumentation in a deployed-style local-agent runtime. These results suggest that boundary-local diagnosis with purified
continuation is a practical direction for protecting
action-capable agents in tool-mediated settings, provided that the
originating source remains recoverable when the injected effect
becomes actionable.

Ethics Considerations
This work studies defenses against indirect prompt injection in
tool-augmented LLM agents. The evaluated attacks are conducted
only in controlled benchmark environments and do not target live
users, real accounts, or production services. Our goal is to reduce
the risk of unauthorized tool use and data exfiltration by enabling
runtime diagnosis and mitigation. We avoid releasing executable
attack code against real systems or instructions that would enable
deployment-specific abuse. The artifacts released with this paper
focus on reproducible benchmark evaluation, defense logic, and
sanitized examples. The study does not involve human subjects or
private user data, and all experiments are performed on public or
synthetic benchmark tasks. The OpenClaw case study uses synthetic workspace artifacts and
sandboxed tools and does not access live user accounts, production
services, or real personal data. We believe these measures mitigate the
main dual-use and operational risks associated with this work.

Appendix C Runtime-Trace and Provenance-Oriented Baselines
Table IV complements the
primary comparison in Table II with
results for AgentArmor, TraceAegis, and ProvSEEK under the same
AgentDojo evaluation settings.
Runtime-trace defenses suppress explicit
execution deviations but remain sensitive to structurally plausible
attack paths.
As shown in
Table IV, AgentArmor and
TraceAegis reduce attack success more consistently when the
injected objective induces a conspicuous change in the tool
sequence or runtime behavior.
Their remaining failures are concentrated primarily under
Tool Knowledge, where injected procedural guidance can
preserve valid tool names, arguments, and high-level control flow.
This pattern is consistent with a limitation of trace-level
enforcement: an execution path may remain structurally admissible
even when the reason for selecting that path has shifted from the
user objective to untrusted mediator content.
AgentArmor’s program-analysis constraints provide comparatively
selective enforcement when an attack introduces an unsupported
transition or violates an explicit execution invariant.
However, such constraints cannot directly determine whether an
otherwise valid transition is justified by the user task or merely
suggested by injected tool documentation.
TraceAegis exhibits a related limitation at the behavioral level.
Legitimate multi-step workflows may contain uncommon branches,
optional tool calls, and model-dependent planning choices, making
it difficult for anomaly detection to distinguish malicious
deviations from benign trajectory diversity.
This ambiguity is consistent with its larger benign intervention
cost.
Provenance evidence does not by itself establish
whether a pending action is user-authorized.
ProvSEEK reconstructs where execution evidence originates and
how it propagates through the agent workflow.
Such information is useful for forensic analysis, but benign and
injected content may enter through the same authorized tool and
therefore exhibit similar provenance structures.
Provenance can identify the source of an artifact without
determining whether the artifact’s influence on a pending action
is consistent with the current user objective.
The results in
Table IV are consistent with
this gap between provenance reconstruction and selective runtime
mitigation: conservative treatment of untrusted provenance can
remove task-relevant evidence, whereas permissive treatment can
leave instruction-bearing influence in the execution state.

Appendix E Mechanism-Targeted Adaptive Stress Grid
The black-box studies use Qwen3-Max at temperature 00 with
(w,δL,δM,γ)=(3,0,0,0.25)(w,\delta_{L},\delta_{M},\gamma)=(3,0,0,0.25).
Each protocol retains its own denominator, and transformations whose
same-case undefended control does not produce the attacker-specified
action are not credited as defense successes.
The adaptive grid contains 36 attack transformations and 36
structure-matched benign controls, each instantiated at
L∈{6,12}L\in\{6,12\} and three trigger positions while preserving the
user goal, host record, attack objective, and effect-bearing tool
signature.
The conditions target distinct components of the pipeline:
trigger-position adaptation stresses the sliding window,
cross-return retrieval stresses grounded evidence assembly,
probe-aware masking evasion stresses the probe contract, and
factual-recipient poisoning stresses the assumption that
effect-bearing values are instruction-bearing.
For each attack, a side-effect-free same-case undefended execution
determines whether the attacker-specified pending action is produced
at all; conditional metrics use the resulting frozen set of 19
activated attacks.
The defended runner is also side-effect-free, so “attack survival”
denotes an unsafe pending action that survives diagnosis rather than
an externally committed effect.
AgentSentry prevents 17 of the 19 activated unsafe pending actions,
giving a conditional survival rate of 10.53%10.53\% with an exact
95%95\% Clopper–Pearson interval of [1.30%,33.14%][1.30\%,33.14\%].
It raises an alarm in 18 of 19 cases and localizes 17 of 19 within
one boundary.
Every activated instruction-bearing transformation is blocked, and
each condition is informative about a different component.
Relocating the trigger does not help the attacker because the local
gate is referenced to the pending proposal rather than to a fixed
offset from the injection: moving the trigger changes which boundary
raises the alarm, not whether one is raised.
Cross-return retrieval is localized exactly in only 2 of 5 cases,
since the attack becomes identifiable only once enough fragments
have entered the state to be associated with a common source set;
the remaining three are still localized within one boundary, so the
cost is a bounded lag rather than diffuse attribution.
Three probe-aware constructions do not activate at all, because the
obfuscation needed to evade the audit contract also weakens the
directive enough that the undefended policy stops adopting it.
Both survivors are factual-recipient-poisoning cases, which lie
outside the operator’s scope by construction.
The mediator supplies the recipient as plausible factual metadata,
so no span satisfies the control-evidence contract of
Section IV-C, purification reduces to the identity,
and both SbMS_{b}^{M} and SbLS_{b}^{L} remain zero.
Replay establishes dependence on removable control content; it does
not adjudicate the truth of a plausible field value.
The three prevented cases in this condition are those where the
poisoned value retains procedural framing that the audit recovers.
Persistent-memory and provenance-spoofing transformations do not
activate, 0 of 6 in each condition, and are not credited as
successes.
Because the grid uses correlated transformations of a small number
of seeds, it is a targeted stress test rather than an i.i.d. sample.
