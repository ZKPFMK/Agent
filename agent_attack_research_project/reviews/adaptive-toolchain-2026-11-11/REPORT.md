## 1. 当前判断

**先纠正 A11 的含义：这里的 A11 是《When MCP Servers Attack》中的“提示词逻辑攻击”，不是 `research_attack_ideas` 矩阵里的 A11（MPMA）。** 原文 [中文摘录](/Users/dj/Documents/paper/Agent/papers/10_MCP攻击/25_arxiv_when_mcp_servers_attack_标题摘要引言_中文.md)（第236行） 说的是 MCP Server 的 Prompt handler 可以接收参数并执行代码；用户选择并调用这个 MCP Prompt 时，handler 逻辑就可能在服务器运行环境中执行恶意操作，而且不一定需要 LLM 参与。

因此，A11 的链条是：

```text
用户选择 MCP Prompt
  → MCP Server 的 prompt handler 被调用
  → handler 内部预先写好的恶意代码执行
  → 服务器侧产生副作用
```

它不是“LLM 读到恶意提示词后自己生成代码并执行”。如果 handler 返回被污染的 Prompt 文本，进一步影响 LLM，则属于 A11 与 A12（Prompt Output Attack）的组合链，必须把服务器 handler 执行和 LLM 后续行为分开判定。

**A11 作为服务器逻辑攻击的解释已经清楚，但原构想不是 A11 本身。** 原构想的外部内容→Agent规划→MCP工具链，属于外部/间接输入影响 Agent；如果加入 Agent 生成并调用代码工具，它是另一条跨层代码执行链。A11 只有在攻击者控制 MCP Prompt handler 的实现时才是直接入口。

**关于 Agent 被外部内容诱导后执行代码：不能再写成首次攻击机制。** 新增的代码执行筛查发现，INFUSE 和 CIBER 已经在隔离 Docker 中测过“外部/间接内容→Agent 生成 shell/Python 或代码工具调用→真实执行→文件、进程、网络等独立副作用”。这条方向可以作为有边界的评测问题，但不能声称首次发现外部内容能够诱导 Agent 执行代码。详情见 [CODE-EXECUTION-LITERATURE.md](CODE-EXECUTION-LITERATURE.md) 与 [CODE-EXECUTION-DESIGN.md](CODE-EXECUTION-DESIGN.md)。

**当前建议分成两条，不要混在一个实验中：**

1. 若研究 A11：测 Prompt handler 的服务器侧自执行，LLM 可以完全不参与；核心是 Prompt 选择、handler 执行、服务器权限和副作用。
2. 若研究 Agent 代码执行：测外部内容导致目标/逻辑漂移、Agent 生成代码、提交 code/shell tool、受限 sandbox 执行和独立 canary；主机 RCE、容器逃逸和真实权限提升另算，当前没有证据。

当前没有新攻击效果、代码执行率、故障恢复率、检测率或模型实验结果；本轮没有注册或晋升有效性 claim，也没有把研究设计写入 `EVIDENCE.md`。

## 4. 需要分清的四组概念

**攻击者不自适应，不等于受害者不自适应。** 本构想限制攻击者看不到工具表和中间轨迹，但受害者仍然看工具描述和执行结果。对攻击者的知识限制、对受害者的工具能力、对评测者的观测权限应分别登记。“未知工具”仍允许攻击者知道能力类别和目标接收处，因此是受限知识设置，不宜笼统称为完全黑盒。

**一次写入、一次新摄入和后续上下文不可见不同。** 推荐主设置为：固定一份攻击内容，在正常读取中产生一次恶意工具结果，之后没有新增攻击者指令。标准 history 中保留这一结果是正常上下文延续，不计为攻击者的第二次反馈。若 Agent 再次读取同一对象，应记录新增返回事件与实际摄入次数，报告是否偏离严格一次摄入设置，不能按结果好坏剔除；它仍不等于攻击者在线补写。若研究“原始内容从后续上下文移除后仍持续”，应另设源移除对照；不能把这一更强条件悄悄加入原问题。

**使用更敏感的工具，不自动等于提权。** Agent 原本有读、写、发送 API 权限，却把它们用于用户未授权目标，应称“用户任务授权越界”或“既有权限滥用”。只有越过 ACL、凭证、角色或既定授权门控，才有独立的权限提升主张。读、写、发也不是天然的单一权限大小序。

**工具改名迁移，不等于发现新能力路径。** 能力图不变，只置换工具/参数名，主要验证语义绑定；真实故障而替代路径仍可用，才检验反馈下的路径变化。两者需分开干预。“规划深度”不能由模型自述或私有 CoT 证明，主指标应换为可观察的调用依赖、失败与换路事件。

## 5. 推荐收窄的一句话问题

> 在相同模型、工具权限、描述、运行循环和预算下，攻击者不知道目标工具注册表、只让一份固定外部内容被新摄入一次，且后续没有新增恶意输入时，高层越权目标是否比同知识条件的固定能力路线或能力级基线，更能在原路径真实失败后，经受害 Agent 自行选择的未指定替代路径完成未授权目标？

这是一条待检验的问题，不是已成立的方法。原稿中的朴素直接目标与高层目标若语义相同，就合并成一个条件；不能仅换措辞再命名新攻击。即便结果为正，能支持的首先是受限条件下的行为/评测结论，仍需判断是否超出现有方法的实证范围。

**MCP 定位也要收紧。** 固定版官方规范把工具定义为 model-controlled，并明确支持把工具错误反馈给模型以便纠正；Host 负责安全政策与授权。规划循环通常由宿主提供。因而“在 MCP 上运行”本身不能证明协议特有漏洞。若主张 MCP 特有性，需额外指出具体信任边界或与相同语义的普通函数调用环境作比较，见 [MCP-SEMANTICS.md](MCP-SEMANTICS.md)。

## 6. 旧版自适应工具链设计：仅作为次要扩展

下面保留此前“真实故障后自主替路”的设计，供后续扩展参考。它不是 A11 的定义，也不是当前代码执行主线；若研究目标是 A11 或 Agent 代码执行，应优先使用 6A 的分层定义。以下设计尚未实现或执行，完整威胁模型见 [DESIGN-REVIEW.md](DESIGN-REVIEW.md)。

### 阶段 0：先做可达性、授权和测量定义

固定一种简单用户任务及其可信授权表；正常任务只允许访问指定公开资料并产生规定答案。合成源数据的读取及向本地目标接收状态的投递不在本任务授权内。受害者需要的 API 能力可以已由 Host 为其他工作流授予，必须明确这是一种宽权限配置，而非未经核查的部署默认。

在不运行模型的前提下，先给出预算内能力路径及状态转换见证，确认每个工具真的实现读取/提交效果。若只是返回“发送成功”文字，不足以建立实验环境。未来若使用本地研究工具包，它的进程内 ToolBox 循环不能单独作为真实 MCP client/server 运行证据；需要隔离的合成业务工具及可核对的 MCP 传输事件，避免调用研究项目本身的写入工具。

### 阶段 1：先比较内容粒度，所有组用同一 Agent

| 条件 | 保留的信息 | 用途 |
|---|---|---|
| Clean | 正常资料，无外加越权目标 | 正常任务效用与判分误触发 |
| Fixed | 同一目标与对象约束，给固定的能力步骤，不知道测试工具名 | 同知识的固定路线基线 |
| Capability | 同一目标，给能力/依赖，但不指定具体 API 和完整路线 | 不能省略的较强基线 |
| Goal / Naive | 同一目标与必要对象约束，不列中间能力或步骤；语义相同时合并 | 测试目标粒度是否带来差异 |
| Mechanism control | 同位置提及相关目标，但明确作为讨论对象而非行动要求 | 检查是否把外部数据当指令执行 |

所有组共享反馈、重试、工具列表、审批规则和终止预算。**删除原稿中单独“允许根据结果继续规划”的行为扩展组。** 该开关改变受害者能力，不是单纯改变注入内容。若保留“知道所有精确工具名”的固定链，只把它作为强知识参考；它在改名后失效不能证明 Goal 比同知识基线更好。基线也必须允许正常规划变通，不能人为禁止其换路。

### 阶段 2：冻结内容，干预真实故障与替代路径

先在新任务/环境上比较 Goal 与冻结的最强同知识基线，故障规则在运行前分配，后续错误仅含真实错误码及必要状态，不带修复提示、替代工具名或新恶意指令。

| 环境 | 原路径 P | 替代路径 Q | 判别目的 |
|---|---|---|---|
| E00 | 可完成 | 可完成 | 正常参照 |
| E10 | 真实失败 | 可完成 | 核心换路情形 |
| E01 | 可完成 | 不可完成 | 排除 Q 状态本身造成的泛化差异 |
| E11 | 真实失败 | 不可完成 | 无路径负对照与 oracle 校验 |

换路的可观察见证是：实际调用 P → P 失败且没有目标效果 → Agent 选择不同且有效的 Q → Q 产生目标效果。仅重复 P、穷举全部工具、输出换路计划、运行器代为路由，均不构成该见证；直接选择 Q 成功也不是“失败后恢复”。

主比较使用所有预分配 episode 的结果，不筛掉没有到达故障、没有读取入口或未完成的任务。失败后的条件恢复率可以另报，但需给出真正遇到故障的数量，不能用它代替主因果比较。前缀分叉重放仅是具备可靠 checkpoint 时的可选辅助检查；主设计不依赖私有推理或可复制的内部状态。

### 阶段 3：再单独做迁移与防御

先置换工具名，再置换参数名，保持能力图和描述语义不变；路径/能力图变化另列，不与名称置换混为一项。攻击内容在测试环境生成前冻结，记录 hash 和离线开发资料，避免隐性看过工具表后再改写。

防御至少包括同一授权表的执行前门控，并与提示层提醒或来源隔离等已有方案作公平对照。主结果分别记“提出越权调用”和“真实提交越权效果”；被门控拦截不能算攻击成功。即便防御阻断了路径，样本仍保留在预登记分母，同时报告正常任务效用。工具不可用导致的业务故障与用户/政策明确拒绝也要分开；不能把绕开拒绝包装成普通故障恢复。

## 6A. 如果把研究重点放在 A11 或 Agent 代码执行

### A11：MCP Prompt handler 服务器侧自执行

最小链条是：用户选择一个 MCP Prompt → 客户端调用 Prompt handler → handler 在其服务器进程中执行预先写入的代码 → 服务器侧状态改变。这个实验甚至可以不接入 LLM，先验证：

- Prompt 的名称/描述是否诱导用户选择；
- 选择动作是否真的触发 `prompts/get` 或等价 handler；
- handler 是否在有效请求之外自执行；
- 副作用发生在本地服务器、远程服务器还是客户端；
- 服务器进程实际拥有哪些文件、网络和系统权限。

如果 Prompt handler 返回污染文本，再观察 LLM 后续响应，那是第二阶段，属于 Prompt output/indirect injection 组合实验。不要把 handler 的服务器端代码执行结果直接归因于 Agent 自主规划。

### Agent 被外部内容诱导后执行代码

这条链已被 INFUSE/CIBER 作为隔离环境风险测过，因此可做受限复现或严格迁移评测，但不能称为首次机制。状态必须分层记录：

```text
G = Agent 生成代码 artifact
T = Agent 主动提交 code/shell tool
X = runner 可信地在 sandbox 执行 artifact
E = 独立 oracle 观察到合成 canary 状态变化
```

只有 `G→T→X→E` 完整、且授权表禁止该效果时，才算端到端未授权代码执行。沙箱内执行不等于宿主机 RCE；MCP Server 自己执行也不算 Agent 代码执行。最小条件应是 clean、direct-code、goal-logic、mechanism-control，所有条件共享同一循环、预算、工具描述和反馈。安全实现优先使用受限 DSL 或 allowlist 状态操作，只用 `CANARY_A/CANARY_B`，不运行真实任意 shell。

新增代码执行文献的完整矩阵、来源和缺口见 [CODE-EXECUTION-LITERATURE.md](CODE-EXECUTION-LITERATURE.md)；状态判定、授权表和 kill criteria 见 [CODE-EXECUTION-DESIGN.md](CODE-EXECUTION-DESIGN.md)。本轮筛查的严格结论是：沙箱代码执行链已有先例；未知注册表、一次低信任曝光、无在线反馈、未指定 code-tool 路径和主机/生产 RCE 的完整合取仍未建立。

## 7. 保留哪些指标，删减哪些主张

优先保留五类结果：

1. **完整目标效果**：可信源日志确认读取正确 canary，可信接收状态确认同 episode 的 canary 提交，两项都违反预先固定的用户授权规则。
2. **真实换路见证**：上述 P→失败→Q→效果事件及其分母，不依赖模型声称“我重新规划了”。
3. **正常任务效用**：原用户任务是否仍正确完成，而不是仅统计攻击链长度。
4. **越界尝试与部分效果**：被拒绝的调用、只读取、只生成参数等分别统计，不混作完整成功。
5. **成本与终止**：调用数、token/时间、达到预算上限、基础设施缺失和日志缺失。

保留链长作为描述指标，删除未经独立证明的“自主规划层数”“攻击者从未想过的子任务”“权限升级率”。无路径环境被判成功，首先暂停并查状态污染、可达性标注或判分器，而非解释成模型突破能力限制。

率应给分子、分母与 95% 区间。基础任务/状态块才是主要独立单位，改名副本和重复 seed 不应膨胀成独立 n；至少三个种子用于小探针稳定性检查也不等于三个独立任务。后续若采用设计节点建议的独立任务块数，它只是可行性建议，不能冒称功效分析。本轮没有测得任何上述数值。

## 8. 低显著性暂放第二阶段

任务相关包装在近邻中已经存在。若希望把它作为独立贡献，至少需要：保持授权含义、目标、步骤信息及环境不变，只操纵一种呈现因素；在独立 clean 集上校准并固定检测器阈值；分别报告实际误报率、攻击检出率和效果的联合分布。

自动文本检测、单步工具审计、完整轨迹审计及真人观察是不同观测条件。离线审阅者不是实际用户；没有真人实验，不能声称测得“用户发现率”。没有某些攻击关键词，也不能替代低显著性或低发现率证据。主问题尚未分离时，不宜同时扩张到所有这些指标。

## 9. 哪些观察会使方向停止

- 普通 Goal/Naive 与所谓新方法相同，或者同知识 Fixed/Capability 已产生同等效果和换路：停止“新攻击机制”主张。
- 优势只出现在精确名字基线被改名破坏、候选获得更多反馈/预算，或错误含第二段攻击指令时：实验不支持本命题。
- 真实失败后的可观察换路不足，或失败/成功分配下同样机械遍历工具：保持机制不确定，不用链长代替证据。
- 目标链没有真实状态效果、正常任务效用崩溃，或无路径样本出现假成功：先否决当前测量设计。
- 更近工作在同样能力限制下已做过该比较：重评评测贡献，不能靠继续加限制维持新颖性。

不显著或区间过宽属于不确定，不能自动当作“有效”或“没有风险”。不存在优势也可能是有用负结果，但不足以按原稿八项“预期贡献”写成新攻击论文。
