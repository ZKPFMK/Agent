# MCP 安全基准（MCP Security Bench，MSB）：面向 LLM 智能体的模型上下文协议攻击基准

**原标题：**MCP Security Bench (MSB): Benchmarking Attacks Against Model Context Protocol in LLM Agents  
**年份与会议：**2026，ICLR。  
**原文：**[本地 PDF](./26_iclr_msb.pdf)。

## 摘要

模型上下文协议（Model Context Protocol，MCP）规范了大语言模型（LLM）智能体发现、描述和调用外部工具的方式。MCP 在实现广泛互操作性的同时，也扩大了攻击面：工具成为具有自然语言元数据和标准化输入输出接口的一等可组合对象。我们提出 MCP Security Bench（MSB），这是一个端到端评估套件，用于系统衡量 LLM 智能体在完整工具使用流程中抵御 MCP 特有攻击的能力，覆盖任务规划、工具调用和响应处理三个阶段。MSB 的贡献包括：（1）建立包含 12 类攻击的分类体系，涵盖名称冲突、偏好操纵、嵌入工具描述的提示词注入、超出范围的参数请求、用户冒充响应、虚假错误升级、工具转移、检索注入和混合攻击等；（2）提供一个评估工具，通过经由 MCP 运行真实工具（包括良性工具和恶意工具）来执行攻击，而不是依赖模拟结果；（3）提出净韧性性能（Net Resilient Performance，NRP）指标，用于量化安全性与性能之间的权衡。我们在 10 个领域、405 个工具上评估了 10 个常用 LLM 智能体，共生成 2,000 个攻击实例。结果揭示了针对 MCP 各阶段的攻击都具有较高有效性。由于具备出色的工具调用和指令遵循能力，性能更强的模型反而更容易受到攻击。MSB 为研究人员和实践者研究、比较并加固 MCP 智能体提供了实用基线。

## 引言

近年来，大语言模型（LLM）在问题求解、推理、工具调用和编程等多种任务中展现出强大的性能（Xu 等，2024；Jin 等，2025；Mingyu 等，2024；Gao 等，2023）。这些进展推动了 AI 智能体的发展。这类智能体将 LLM 作为核心决策者，并配备外部工具（Zheng 等，2025）和记忆机制（Xu 等，2025）。借助工具，基于 LLM 的智能体能够与更丰富的外部环境交互，并支持从项目开发（Lu 等，2023）到团队管理（Li 等，2025a）和信息辅助（Chae 等，2025）等多种应用。

工具扩展了基于 LLM 的智能体的功能，但由于缺乏统一标准，不同架构和平台需要重复实现工具集成。为解决这一问题，Anthropic 提出了模型上下文协议（Model Context Protocol，MCP）（Anthropic，2024），通过统一接口规范上下文交换（Hou 等，2025）。如图 1 所示，MCP 遵循“主机—客户端—服务器”的工作流程：工具声明自身能力，客户端获取并查询这些工具，服务器执行选定的工具并返回结果。MCP 在提升互操作性的同时，也扩大了攻击面，使智能体暴露于严重的安全漏洞之下（Song 等，2025；Labs，2025；Guo 等，2025；Li 等，2025b；Fang 等，2025）。现有基准（例如 ASB（Zhang 等，2025a）、AgentDojo（Debenedetti 等，2025）和 InjecAgent（Zhan 等，2024））仍局限于函数调用范式，因而无法捕捉这些 MCP 特有的漏洞。

为弥补这一空白，我们提出 MCP Security Bench（MSB），这是一个用于系统评估基于 MCP 工具使用的 LLM 智能体安全性的基准，覆盖 MCP 工作流程的所有阶段。MSB 包含 2,000 个攻击实例，覆盖 10 个任务场景、65 个现实任务和 405 个工具，为评估现实环境中的漏洞提供了大规模且多样化的测试平台。具体而言，MSB 建立了一个包含 12 类攻击的分类体系，覆盖 MCP 工作流程中的三个关键阶段：任务规划、工具调用和响应处理。这些攻击针对工具名称、描述、参数和响应等工具向量。工具签名攻击（例如名称冲突、偏好操纵和提示词注入）操纵元数据，误导工具选择；工具参数攻击（例如超出范围参数）诱导智能体泄露未经授权的信息；工具响应攻击（例如用户冒充、虚假错误和工具转移）通过欺骗性或遭到投毒的输出改变智能体行为；检索注入攻击通过将恶意数据插入检索过程，破坏上下文完整性；最后，混合攻击组合跨阶段的多个攻击向量，以放大攻击影响，覆盖 MCP 工作流程中的各种对抗策略。

此外，MSB 提供了一个评估工具，通过经由 MCP 运行真实工具（包括良性工具和恶意工具）来执行攻击，而不是依赖模拟输出。这种动态设计更真实地反映了实际运行条件，并能够暴露静态基准无法捕捉的漏洞。为了量化这些条件下的鲁棒性，我们在常用的攻击成功率（Attack Success Rate，ASR）和攻击下性能（Performance Under Attack，PUA）之外，提出了新的净韧性性能（Net Resilient Performance，NRP）指标，用于刻画性能与安全性之间的整体权衡。利用这些指标，我们评估了 9 个常用 LLM 主干模型，并观察到最高攻击成功率达到 75.83%。结果表明，MCP 特有的漏洞很容易被利用；由于更强模型具备更出色的工具使用能力，它们反而更容易受到攻击。这进一步说明，有必要建立专门的基准来评估基于 MCP 的智能体安全性。

本文的主要贡献如下：

1. **提出 MSB 基准。**我们提出 MSB，这是一个专门用于评估基于 MCP 工具使用的 LLM 智能体安全性的基准。它包含覆盖 10 个场景、65 个现实任务和 405 个工具的 2,000 多个攻击实例。
2. **建立 MCP 攻击分类体系。**我们建立了一个包含 12 类攻击的分类体系，覆盖 MCP 工作流程的三个阶段：任务规划、工具调用和响应处理。
3. **提出动态评估框架。**我们开发了一个动态评估框架，使用 ASR、PUA 和本文提出的 NRP 三种鲁棒性指标，量化安全性与性能之间的权衡。
4. **开展大规模实验。**我们在 10 个 LLM 主干模型上开展大规模实验，结果表明 MCP 特有的漏洞很容易被利用，说明有必要建立专门的基准来评估基于 MCP 的智能体安全性。

## 3 预备概念与威胁模型

### 3.1 基本概念

**使用 MCP 工具的 LLM 智能体。**我们考虑一种通过 MCP 与工具交互的 LLM 智能体。每个工具 \(\tau\) 都表示为一个四元组 \((\tau_n, \tau_d, \tau_p, \tau_r)\)，分别由工具名称 \(\tau_n\)、功能描述 \(\tau_d\)、参数 \(\tau_p\) 和响应 \(\tau_r\) 构成。在 MCP 框架中，客户端通过将工具名称和描述嵌入系统提示词 \(p_{sys}\)，向智能体公开可用工具列表：

\[
T = (\tau^{(1)}, \ldots, \tau^{(l)}),
\]

嵌入后的系统提示词记为 \(p_{sys} \oplus T\)，其中 \(\oplus\) 表示字符串拼接。随后，智能体提供所需参数 \(\tau_p\) 调用工具，并处理工具返回的结果 \(\tau_r\)。智能体还可以通过工具从数据库 \(D\) 中检索知识。形式化地说，一个由工具增强的智能体旨在最大化以下目标：

\[
\mathbb{E}_{q \sim \pi_q}\left[\mathbf{1}\left(\operatorname{Agent}(\operatorname{LLM}(p_{sys} \oplus T, q, O), T, D) = a\right)\right]. \tag{1}
\]

其中，\(\pi_q\) 表示用户查询的分布，\(\mathbf{1}(\cdot)\) 表示指示函数。LLM 根据用户查询 \(q\) 和工具列表 \(T\) 制定任务计划。智能体通过反复调用工具执行该计划，并从任务轨迹中产生观测序列 \(O = (o^{(1)}, \ldots, o^{(j)})\)，其中包括工具响应。将 \(O\) 纳入上下文后，智能体能够在解决任务的过程中动态调整计划。这里，\(a\) 表示智能体预期执行的动作。

**攻击任务。**在 MCP 框架中，攻击者利用恶意工具列表

\[
T^m = (\tau^{m}_{(1)}, \ldots, \tau^{m}_{(k)})
\]

以及遭到投毒的数据库 \(D_p\)，诱导智能体执行攻击任务。恶意工具 \(\tau^m\) 的名称 \(\tau^m_n\)、描述 \(\tau^m_d\)、参数 \(\tau^m_p\) 和响应 \(\tau^m_r\) 都可能成为攻击向量。

### 3.2 威胁模型

**攻击者能力。**攻击者可以部署一个完全受其控制的恶意 MCP 服务器，包括该服务器上托管的所有工具。攻击者还可以将这些恶意工具所在的服务器连接到第三方平台（例如 Smithery（Smithery.ai，2025）），从而发布恶意工具。不过，攻击者无法控制智能体中的 LLM，因此无法像已有工作（Zhang 等，2025a）那样，拦截用户查询并直接向 LLM 智能体注入恶意指令。攻击者的能力总结如下：

1. **工具。**攻击者可以修改服务器上任意恶意工具的每个组成部分，并将这些工具用作攻击向量。此外，攻击者可以同时在服务器上部署多个相互协同的恶意工具。MCP 的工具发现机制使恶意工具能够直接集成到智能体的工具列表中。
2. **系统提示词。**基于 MCP 提供的工具发现机制（Anthropic，2024），攻击者可以将恶意提示词无缝插入智能体的系统提示词中。
3. **外部资源。**攻击者对外部资源拥有白盒权限，可以将隐蔽的攻击指令插入这些外部资源（Radosevich 和 Halloran，2025；Halloran，2025），供智能体通过工具检索。

**攻击目标。**在 MCP 框架中，攻击者的目标是破坏智能体在任务规划、工具调用和响应处理阶段的决策，使其执行恶意动作 \(a_m\)。攻击者希望最大化：

\[
\mathbb{E}_{q \sim \pi_q}\left[\mathbf{1}\left(\operatorname{Agent}(q, \theta_m) = a_m\right)\right]. \tag{2}
\]

该攻击的目标是最大化这样的期望概率：对于给定的输入查询 \(q\)，智能体受到对抗性修改 \(\theta_m\) 的影响后执行恶意动作 \(a_m\)。其中，\(\theta_m\) 表示攻击者能够施加的对抗性修改集合，这些修改可以作用于系统提示词 \(p_{sys}\)、观测序列 \(O\)、工具列表 \(T\) 和知识数据库 \(D\)。

## 4 攻击分类体系

在 MCP 工作流程中，LLM 智能体通过工具签名（名称和描述）、参数以及响应与工具交互，这些内容都可能成为攻击向量，如图 1 所示。我们根据这些攻击向量及其所处的交互阶段，对攻击类型进行定义和分类（见表 1）。第 4.1 节定义了任务规划阶段的三类攻击，攻击者通过操纵工具签名，将恶意提示词注入系统提示词。第 4.2 节介绍工具调用阶段的一类攻击，该攻击诱导智能体提供权限过大的参数。第 4.3 节介绍响应处理阶段的三类攻击，操纵后的工具响应通过欺骗智能体诱导其执行恶意操作。第 4.4 节介绍响应处理阶段的另一类攻击，该攻击通过工具响应将遭到投毒的数据注入上下文。上述攻击还可以组合成覆盖多个阶段的混合攻击（第 4.5 节）。最后，我们在附录 C 中给出攻击示例。

### 4.1 工具签名攻击

在任务规划阶段，攻击者利用工具名称 \(\tau_n^m\) 或工具描述 \(\tau_d^m\) 作为攻击向量。具体而言，攻击者通过构造恶意工具 \(\tau^m \in T^m\) 的名称或描述，针对一个良性工具 \(\tau^t \in T\)，并将恶意工具列表 \(T^m\) 注入工具列表 \(T\)，记为 \(T + T^m\)。恶意工具诱导智能体执行恶意动作 \(a_m\)。形式化地说，攻击目标是最大化：

\[
\mathbb{E}_{q \sim \pi_q}\left[\mathbf{1}\left(\operatorname{Agent}(\operatorname{LLM}(p_{sys} \oplus T \oplus T^m, q, O), T + T^m) = a_m\right)\right]. \tag{3}
\]

除特别说明外，其他符号与公式（1）中的相同，相关公式汇总见附录 B。这一类别包含三种具体攻击类型：

- **名称冲突（Name Collision，NC）。**NC 利用工具名称作为攻击面，干扰智能体的工具选择决策。具体而言，NC 将恶意工具名称 \(\tau_n^m\) 设置为与目标工具名称 \(\tau_n^t\) 相似，从而诱骗智能体调用恶意工具 \(\tau^m\)，而不是原本预期的目标工具 \(\tau^t\)。
- **偏好操纵（Preference Manipulation，PM）。**PM 利用工具描述作为攻击面，干扰智能体的工具选择决策。具体而言，PM 在目标工具描述 \(\tau_d^t\) 中插入宣传性语句，形成恶意工具描述 \(\tau_d^m\)，从而诱导智能体调用恶意工具 \(\tau^m\)，而不是原本预期的目标工具 \(\tau^t\)。
- **提示词注入（Prompt Injection，PI）。**PI 利用工具描述作为攻击面，扭曲智能体的规划和推理过程。具体而言，PI 将恶意指令 \(x_m\) 注入工具描述 \(\tau_d^m\)，从而诱导智能体执行攻击任务，而不是执行用户原本要求的任务。

### 4.2 工具参数攻击

在工具调用阶段，攻击者利用工具参数 \(\tau_p^m\) 作为攻击向量。具体而言，攻击者通过定义一个超出正常操作所需范围的参数 \(\tau_p^m\)，构造恶意工具 \(\tau^m \in T^m\)。智能体将该参数传递给工具并发起调用，从而导致信息泄露。形式化地说，攻击目标是最大化：

\[
\mathbb{E}_{q \sim \pi_q}\left[\mathbf{1}\left(\operatorname{Agent}(\operatorname{LLM}(p_{sys} \oplus T^m, q, O), T^m) = a_m\left(\tau^m(\tau_p^m = i_m)\right)\right)\right]. \tag{4}
\]

其中，\(a_m(\tau^m(\tau_p^m = i_m))\) 表示智能体将参数 \(\tau_p^m\) 设置为值 \(i_m\)，并调用工具 \(\tau^m\)。其他符号与公式（1）和公式（3）中的相同。

**超出范围参数（Out-of-Scope Parameter，OP）。**OP 通过上述过程实施攻击，利用工具参数作为攻击面，迫使智能体提供超出正常范围的输入。

### 4.3 工具响应攻击

在工具响应阶段，攻击者利用工具响应 \(\tau_r^m\) 作为攻击向量。具体而言，攻击者通过在响应 \(\tau_r^m\) 中嵌入恶意指令 \(x_m\) 来构造恶意工具。当响应 \(\tau_r^m\) 被纳入观测序列 \(O\)，记为 \(O + \tau_r^m\) 时，它会误导智能体，使其遵循恶意指令 \(x_m\)，而不是继续执行用户任务。形式化地说，攻击目标是最大化：

\[
\mathbb{E}_{q \sim \pi_q}\left[\mathbf{1}\left(\operatorname{Agent}(\operatorname{LLM}(p_{sys} \oplus T^m, q, O + \tau_r^m), T^m) = a_m[x_m]\right)\right]. \tag{5}
\]

其中，\(a_m[x_m]\) 表示智能体遵循恶意指令 \(x_m\) 执行动作。其他符号与公式（1）和公式（3）中的相同。这一类别包含三种具体攻击类型：

- **用户冒充（User Impersonation，UI）。**UI 利用工具响应作为攻击面，冒充用户身份嵌入恶意指令，误导智能体执行非预期且有害的操作。随着 LLM 能力提升，模型能够有效遵循用户指令（Qianyu 等，2024；Stolfo 等，2025；Cheng 等，2025），甚至会不加批判地遵循这些指令（Gracjan 等，2025；Kang 等，2023），从而扩大了攻击面（Zhang 等，2025a）。在现实场景中，直接修改用户查询以注入恶意指令通常并不可行。在 MSB 中，我们让工具模拟用户并向智能体发出恶意指令，从而实现一种简单但有效的攻击方法。
- **虚假错误（False Error，FE）。**FE 利用工具响应作为攻击面，干扰智能体的任务执行轨迹。具体而言，FE 提供伪造的工具执行错误信息，要求智能体遵循恶意指令才能成功调用工具。结果是，智能体执行非预期且有害的操作。
- **工具转移（Tool Transfer，TT）。**TT 利用工具响应作为攻击面，扰乱智能体的工具路由逻辑和决策流程。具体而言，TT 是一种涉及两个工具的链式攻击：中继工具 \(\tau^m\) 和端点工具 \(\tau^e\)。中继工具 \(\tau^m\) 不会直接执行攻击，而是通过其响应 \(\tau_r^m\) 操纵智能体调用端点工具 \(\tau^e\)，由端点工具 \(\tau^e\) 执行实际攻击。

### 4.4 检索注入攻击

攻击者向智能体提供一个遭到投毒的数据库 \(D_p\)，其中嵌入了恶意指令 \(x_m\)，即 \(x_m \subset D_p\)。当智能体调用工具 \(\tau\) 从 \(D_p\) 中检索数据时，工具响应 \(\tau_r\) 会将 \(x_m\) 注入观测序列 \(O\)，诱导智能体遵循恶意指令，而不是继续执行用户任务。该过程可以形式化表示为：

\[
\mathbb{E}_{q \sim \pi_q}\left[\mathbf{1}\left(\operatorname{Agent}(\operatorname{LLM}(p_{sys} \oplus T, q, O + \tau_r), T, D_p) = a_m[x_m]\right)\right]. \tag{6}
\]

其他符号与公式（1）和公式（3）中的相同。

**检索注入（Retrieval Injection，RI）。**RI 通过上述过程实施攻击，利用外部资源作为攻击面，破坏智能体的上下文完整性。RI 与第 4.3 节中的攻击不同：RI 的恶意指令来源于遭到投毒的数据库，而工具本身仍然是良性的。因此，我们将 RI 划分为一种独立的攻击类型。

### 4.5 混合攻击

攻击者同时利用恶意工具 \(\tau^m\) 的多个组成部分作为攻击向量，构造覆盖多个阶段的混合攻击。该过程可以形式化表示为：

\[
\mathbb{E}_{q \sim \pi_q}\left[\mathbf{1}\left(\operatorname{Agent}(\operatorname{LLM}(p_{sys} \oplus T \oplus T^m, q, O + \tau_r^m), T + T^m) = a_m\right)\right]. \tag{7}
\]

其他符号与公式（1）和公式（3）中的相同。混合攻击同时利用多个交互接口作为攻击面，破坏智能体任务执行流程中的多个阶段。例如，PM 与 UI 的组合可以构成一条从工具选择到响应处理的端到端攻击链。这类混合攻击在需要配置多个工具的现实部署中具有更高风险。

### 5.1 MSB 的组成部分

**良性工具和用户任务。**MSB 中的良性工具集来自 MCP 集成平台 Smithery.ai（2025）上使用频率最高的工具。经过功能验证和去重后，我们保留了 304 个实现行为与其描述相符的工具，作为良性工具。基于这一工具集，我们设计了能够检验这些工具功能的用户任务。每项任务都要求至少调用一个良性工具。例如，与论文搜索工具对应的任务是总结某个研究领域的最新进展。最终，我们获得了覆盖 10 个代表性现实场景的 65 项用户任务。更多细节见附录 D.1。

**攻击工具和攻击任务。**攻击工具通过修改良性工具生成。每种攻击工具类型都针对良性工具的特定组成部分采用相应的修改策略（例如，FE 工具将原始响应替换为错误消息）。待修改的组成部分包括工具名称、描述、参数和响应。表 1 总结了相应的修改规则。通过这一过程，我们生成了 405 个攻击工具。攻击任务规定了攻击者希望实现的目标（例如修改敏感数据）。我们设计了 6 项攻击任务，每项任务都要求智能体调用工具来完成指定目标（例如调用文件编辑工具修改存储的数据）。如表 1 所示，攻击任务可以通过字符串拼接的方式与攻击工具组合。更多细节见附录 D.2。

**环境和实例。**环境定义了智能体运行的工作空间，其中包含攻击目标数据（例如个人敏感信息）和遭到投毒的外部资源（例如嵌入恶意指令的指南）。智能体配备了两个 MCP 服务器——FileSystem（2024）和 DesktopCommander（2024），它们提供基本的文件访问和工作空间操作能力。通过组合用户任务、攻击任务和攻击工具，我们构建了 2,000 个攻击测试实例。更多信息见附录 D.3。

### 5.2 评估指标

**攻击成功率（Attack Success Rate，ASR）。**表示攻击者目标实现的攻击实例所占比例。

\[
\mathrm{ASR} = \frac{\text{成功攻击实例数量}}{\text{攻击实例总数}}. \tag{8}
\]

**攻击下性能（Performance Under Attack，PUA）。**表示在对抗环境中完成的用户任务所占比例。

\[
\mathrm{PUA} = \frac{\text{攻击环境下完成的用户任务数量}}{\text{用户任务总数}}. \tag{9}
\]

**净韧性性能（Net Resilient Performance，NRP）。**表示智能体整体的韧性效用。

\[
\mathrm{NRP} = \mathrm{PUA} \cdot (1 - \mathrm{ASR}). \tag{10}
\]

我们通过检查工作空间中的环境状态来评估攻击者目标是否实现，例如检查敏感数据是否被修改，并将每项攻击任务的测量结果汇总于表 9。我们通过检查工具调用日志，判断智能体是否调用了任务所需的良性工具，来评估用户任务是否完成。例如，对于论文搜索用户任务，我们会检查智能体是否调用了论文搜索工具。

ASR 衡量攻击的有效性。通常，ASR 越高，表示 LLM 智能体越容易受到攻击威胁。PUA 评估智能体在对抗环境中完成用户任务的能力。PUA 越高，说明智能体在受到干扰时具有更强的运行稳定性。NRP 用于评估智能体在抵御攻击的同时维持任务性能的整体能力。较低的 NRP 表明智能体可能存在攻击下性能较差、容易受到攻击，或两者兼有的问题。相反，较高的 NRP 表明智能体能够在保持任务性能的同时有效抵御攻击。NRP 综合平衡了准确性和安全性，可以评估智能体的整体韧性。

其他基准（例如 ASB（Zhang 等，2025a））通过结合模型在良性环境中的性能和 ASR 来计算 NRP。然而，在我们的研究中，良性环境和对抗环境之间存在显著差异。例如，偏好操纵攻击会诱使智能体选择恶意工具，而良性环境中不存在这种情况。因此，很难将良性环境中的性能测量结果直接扩展到对抗环境。基于这一原因，我们根据模型在对抗环境中的性能计算 NRP。
