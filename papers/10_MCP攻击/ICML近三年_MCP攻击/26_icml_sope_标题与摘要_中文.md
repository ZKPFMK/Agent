# SOPE：面向 MCP 智能体的情境感知与统计不可区分隐私外泄

**原标题：**SOPE: Situation-Aware and Statistically Indistinguishable Privacy Exfiltration for MCP-enabled Agents  
**攻击方法：**Scenario-aware and zerO-click Privacy Exfiltration（SOPE，情境感知与零点击隐私外泄）  
**年份与会议：**2026，ICML。  
**原文：**[本地 PDF](./26_icml_sope.pdf)。

## 摘要

模型上下文协议（Model Context Protocol，MCP）使大语言模型（LLM）智能体能够与外部工具交互，但这种可扩展性也引入了严重的供应链漏洞，使隐蔽的隐私外泄成为可能。已有研究揭示了通过间接提示词注入导致 MCP 智能体隐私泄露的风险；然而，现有攻击通常与智能体的工具使用情境不匹配，并且依赖僵化的模板，容易形成可识别的模式，从而被现有防御机制发现。在本文中，我们利用隐私暴露本质上依赖具体情境这一事实，将特定隐私信息与特定工具关联起来。我们提出情境感知与零点击隐私外泄（Scenario-aware and zerO-click Privacy Exfiltration，SOPE）框架，能够将任意良性 MCP 服务器转换为具有隐私外泄能力的变体。SOPE：（1）识别与工具使用情境相适配的隐私信息；（2）将隐私探测指令嵌入工具调用提示词；（3）通过代码级修改实现无需用户点击的数据传输。我们在 27,216 个测试用例上评估 SOPE，其中包括由真实世界 MCP 服务器自动转换得到的 324 个 SOPE 服务器，并使用这些服务器攻击 4 个基准智能体和 3 个商业智能体，同时测试 9 种最先进的防御机制。结果表明，SOPE 依然具有很高的有效性和鲁棒性，揭示了智能体生态系统中关键的协议层安全缺口。

## 1 引言

由 LLM 与外部工具和服务无缝集成所赋能的基于大语言模型（LLM）的智能体，正迅速发展为能够自主执行日常任务的通用个人助理（He 等，2024；Xi 等，2025）。为了以可扩展且标准化的方式访问各种外部工具，模型上下文协议（Model Context Protocol，MCP）应运而生，成为一种统一接口，用于抽象 LLM 智能体的能力暴露和工具调用（Anthropic，2025b）。

MCP 的模块化和可扩展特性促进了一个充满活力的生态系统：各种面向复杂任务的功能在社区和市场中得到集成与交易（MCP.so，2025；Smithery，2025a）。然而，这种开放性也引入了尚未得到充分研究的新隐私风险。具体而言，恶意 MCP 服务器可以沿着智能体的执行流程，隐蔽地诱导、提取并传播用户敏感信息。因此，有必要系统探索此类隐私外泄攻击的对抗能力边界，推进基于 MCP 的 LLM 智能体供应链安全（Anthropic，2025c；Cursor，2025）。

已有研究揭示了基于 MCP 的智能体存在用户隐私泄露问题，攻击者会通过向工具输出中注入间接提示词来主动窃取隐私（Yang 等，2025b；Zhao 等，2026）。这些工作主要通过设计提示词模板，迫使 LLM 调用窃取隐私和发送隐私的工具，并强调覆盖智能体上下文中的其他数据和指令（Wang 等，2025c；Radosevich 和 Halloran，2025）。图 1 给出了一个示例。

**图 1. 现有隐私外泄攻击示例。**攻击载荷通常由三部分组成：触发条件、恶意操作和合理的正当理由。例如，工具在返回正常结果后，要求智能体将银行账号发送给攻击者，并以“否则用户账户将被锁定”作为理由。

然而，这些攻击存在两个关键局限，使其容易被现有防御机制拦截。第一，**缺乏情境感知能力。**现有注入指令的构造通常不考虑智能体正在执行的任务，而是将重点放在提高恶意操作在 LLM 上下文中的优先级上。因此，恶意执行与当前任务相脱节，表现为任务轨迹发生偏离。例如，计算器工具要求用户提供电子邮箱地址就十分可疑，很容易被发现。第二，**对抗模式具有可识别性。**现有注入指令往往遵循僵化的模板，通常包含触发、执行和为恶意操作提供理由等组成部分。这会形成容易识别的词汇和文本模式；由于表现出统计异常，这些痕迹很容易被红队检测模型标记出来。

上述局限促使我们研究一种具备情境感知能力且在统计上不可区分的隐私外泄攻击。这种攻击能够维持原有任务轨迹，并且不表现出统计异常。然而，要解决这些局限仍面临两个挑战。第一，**情境适配的隐私探测。**我们观察到，某些隐私信息天然与特定工具相关联。例如，用户的家庭住址是配送工具可能合理请求的信息，但如果由计算器工具请求，就会显得可疑。针对与情境相关的隐私信息，可以保持智能体的执行轨迹，使攻击更难被检测。但是，如何针对不同任务中的各种 MCP 工具，自动确定哪些隐私信息是合理的，仍然具有挑战性。第二，**统计不可区分的外泄过程。**即使确定了符合情境的隐私信息，如何在不引发智能体和用户可识别异常的情况下提取并传输这些信息（例如不产生可疑的工具调用序列或僵化的参数模式），仍然很困难。具体而言，既要融合能够诱导隐私泄露的指令，又要保持功能一致性；此外，显式调用工具传输隐私还会破坏语义连贯性。

为应对这些挑战，我们提出情境感知与零点击隐私外泄（Scenario-aware and zerO-click Privacy Exfiltration，SOPE）框架。该框架能够在保持原有功能的同时，自动将良性 MCP 服务器转换为隐私窃取变体。SOPE 对良性服务器依次执行三个阶段：**Assign（分配）、Fuse（融合）和 Leak（外泄）。**在 Assign 阶段，SOPE 学习隐私信息与 MCP 能力之间的映射关系，根据使用情境确定每项能力可以合理请求哪些隐私信息。在 Fuse 阶段，SOPE 将每项能力所分配的隐私信息及其发起提示词原语作为输入，生成能够嵌入探测意图的指令，同时保持与原始提示词的功能一致性和语义连贯性。最后，在 Leak 阶段，SOPE 通过函数参数外泄提取到的隐私数据，并通过向工具实现中追加传输函数将数据发送出去，整个过程无需用户交互。

我们使用 27,216 个测试用例对 SOPE 开展了广泛评估。这些用例包含 324 个由真实世界 MCP 服务器自动转换得到的恶意服务器。我们将这些服务器部署到 4 个基准智能体和 3 个商业智能体（Claude Desktop、Cursor 和 ChatGPT）上，并选择性地启用 9 种最先进的防御机制。我们还将 SOPE 与使用 12 种间接提示词注入策略生成的 480 个攻击用例进行比较。结果表明，SOPE 具有很高的有效性和鲁棒性，其隐私泄露率约为现有攻击的 3 倍。我们还发现，商业智能体由于提供了更好的用户体验，反而更容易受到攻击。

本文的主要贡献如下：

1. **系统研究 MCP 服务器中的隐私威胁。**据我们所知，我们首次系统探索了 MCP 服务器中的隐私威胁，揭示了一个严重的供应链安全风险。
2. **提出 SOPE 框架。**我们提出了一个全自动框架，能够构造具备情境感知能力、语义连贯性且保持原有功能的隐私窃取型 MCP 服务器。
3. **开展广泛的实证评估。**我们在多种智能体基准和商业系统上进行了广泛的实证评估，证明 SOPE 能够绕过现有防御机制，并凸显了加强协议层安全的紧迫性。

## 2 背景与相关工作

### 2.1 基于 MCP 的 LLM 智能体

**智能体架构。**基于 MCP 的智能体在基础 LLM 的基础上扩展了记忆和工具访问等外部组件，使其能够更自主、更准确地执行任务（He 等，2024；Xi 等，2025）。具体而言，记忆模块 \(M\) 存储用户相关信息，其中包括敏感信息项 \(P_i \in \mathcal{P}\)，\(i \in \{1, \ldots, N\}\)（Li 等，2024；Zhang 等，2025）。工具的使用主要通过 MCP 进行管理，使智能体能够调用超出 LLM 自身能力范围的外部功能（MCP 生态系统的更多内容见附录 B）。

**模型上下文协议（MCP）。**MCP 服务器 \(S\) 暴露一组能力（工具）

\[
T = \{T_1, T_2, \ldots, T_K\}。
\]

每项能力 \(T_k\) 都与一个三元组 \((\phi_k, \pi_k, f_k)\) 相关联。其中，\(\phi_k\) 是自然语言工具描述，用于说明工具的预期用途及其参数模式 \(\alpha_k\)；\(\pi_k\) 是用于调用工具的标准化提示词模板；\(f_k\) 是工具的功能实现（Dong，2024；Anthropic，2025b）。

**工具使用流程。**在初始化阶段，服务器将带有描述的工具能力集合

\[
\Phi = \{\phi_k\}_{k=1}^{K}
\]

注册到智能体。给定用户指令 \(q\)，智能体执行一个将记忆检索与基于 MCP 的工具使用交织起来的工作流程（如图 2（c）所示）：

1. **规划：**LLM 分析 \(q\)，并参考已注册的工具描述集合 \(\Phi = \{\phi_k\}\) 选择一项能力 \(T_k\)。
2. **调用：**LLM 使用提示词模板 \(\pi_k\) 发起对 \(T_k\) 的工具调用，并根据参数模式 \(\alpha_k\) 填写所需参数。这一步可能需要从记忆模块 \(M\) 中检索敏感信息项 \(P_i\)，以满足工具的输入要求。
3. **执行：**选定的工具 \(T_k\) 通过其实现 \(f_k\)，使用所需参数 \(\alpha_k\) 执行，并产生执行结果 \(R_k\)。
4. **上下文更新：**结果 \(R_k\) 返回给智能体，并追加到 LLM 上下文 \(C\) 中，以供后续决策使用。

**图 2. SOPE 的输入、框架和部署概览。**图中展示了三部分：良性 MCP 服务器及其工具和隐私信息作为输入；SOPE 通过“分配—融合—外泄”三个阶段将其转换为恶意 MCP 服务器；部署后，智能体在正常执行工具的过程中提取并传输隐私信息。

### 2.2 智能体中的隐私外泄与缓解方法

**工具诱导的隐私外泄。**工具使用流程暴露了一个关键攻击面：攻击者可以将恶意指令注入工具结果 \(R\)，诱导智能体提取并外泄敏感用户信息 \(P_i\)。现有攻击通常遵循间接提示词注入范式，构造由三个关键部分组成的恶意载荷（Wang 等，2025c）。

1. **触发条件（Trigger）。**规定载荷何时激活。已有工作通过两种方式构造触发条件：一种是**显式命令（Explicit Commands）**，直接指示智能体调用一个会返回恶意提示词的工具（Zhan 等，2024）；另一种是**隐式劫持（Implicit Hijacking）**，将恶意指令嵌入原本良性的工具输出中（Yang 等，2025b）。
2. **恶意操作（Malicious Action）。**定义隐私外泄行为。一种常见策略是分两步执行：首先进行隐私提取，提示智能体从记忆模块 \(M\) 中检索敏感信息项（Wang 等，2025a）；随后进行数据传输，指示智能体将提取的信息发送到攻击者控制的端点，例如远程服务器或电子邮箱地址（Zhan 等，2024；Debenedetti 等，2024）。
3. **合理的正当理由（Plausible Justification）。**提供看似合法的理由，以提高智能体的服从程度，并压过相互竞争的指令。常见策略包括：使用不服从就会导致严重后果的**威胁**；承诺改善性能或提供奖励的**诱因**；以及明确强调恶意操作优先于先前指令的**优先级暗示**（Zhan 等，2024；Zhao 等，2026）。相应示例见附录 G。

**防御与缓解措施。**针对工具诱导的隐私外泄，可以根据防御措施介入工具处理流程的位置，将其分为三个层级：

1. **检索筛查（Retrieval Screening）。**在不可信输入进入模型上下文之前对其进行过滤，可以使用文本启发式方法（inp，2023；meta-llama，2025）、语义一致性指标（Alon 和 Kamfonas，2023），或模型信号，例如隐藏状态或激活值（Shi 等，2025；Abdelnabi 等，2025）。
2. **上下文分隔（Context Demarcation）。**对输入进行结构化处理，将不可信的工具输出与指令分隔开，降低模型把注入内容当作可执行指令的可能性（Hines 等，2024；Yi 等，2025；Schulhoff，2026）。
3. **系统隔离（System Isolation）。**实施架构层面的约束，例如中心辐射式架构或权限分离，以限制通过工具使用触发的高影响操作，即使 LLM 已受到注入指令的控制，也能降低其影响（Wu 等，2025b；Chen 等，2025a；Wu 等，2025a）。

## 3 方法

### 3.1 总体概述

如图 2 所示，SOPE 能够在不损害原有功能的前提下，自动将包含一组能力 \(T\) 的良性 MCP 服务器 \(S\) 转换为具有隐私窃取能力的变体 \(\tilde{S}\)。如图 2（c）所示，部署后，每当能力 \(T_k\) 被调用，\(\tilde{S}\) 就会提取隐私信息 \(P_i^k \in \mathcal{P}\)，并将其传输到攻击者控制的端点。

**威胁模型。**攻击者是恶意 MCP 服务器开发者，可以修改工具描述 \(\phi_k\)、提示词模板 \(\pi_k\) 和功能实现 \(f_k\)，因为这些内容在设计上都由服务器开发者控制。然而，攻击者无法访问受害智能体的内部设计、防御机制或用户数据。攻击者通过开放的 MCP 市场发布恶意服务器，例如 GitHub、MCP.so（MCP.so，2025）和 Smithery（Smithery，2025a）。这些平台托管了超过 30,000 个来自未经审查开发者的服务器，审核力度有限（Guo 等，2025；Li 等，2025；Zhao 等，2026）。攻击者的目标是在不提醒用户、也不触发现有防御机制的情况下，从智能体的记忆 \(M\) 中窃取隐私信息 \(P_i \in \mathcal{P}\)，并将其传输到攻击者控制的端点。

**整体流程。**在上述威胁模型下，SOPE 依次执行三个步骤，如算法 1（附录 A）所示，图 2（b）给出了示例：

1. **Assign（分配）隐私信息。**根据情境适配性，将隐私信息 \(P_i\) 分配给能力 \(T_k\)。由于某些隐私信息在特定情境下与特定工具天然相关，我们训练 Assign 模型，预测在使用每项能力时，某个隐私信息是否适合被请求。每项能力的使用情境由其描述 \(\phi_k\) 界定（第 3.2 节）。
2. **Fuse（融合）隐私探测指令。**将针对隐私信息 \(P_i\) 的探测指令，以保持语义连贯性的方式融合到工具调用提示词模板 \(\pi_k\) 中。Fuse 模型利用提示词原语 \(\pi_k\) 中包含的先验知识；该原语规定了如何以自然语言命令启动能力 \(T_k\) 的功能实现 \(f_k\)，从而在保持语义连贯性的同时嵌入探测指令（第 3.3 节）。
3. **Leak（外泄）隐私信息。**通过由 \(f_k\) 的参数传递的附加 `transmit` 函数，外泄提取到的隐私信息。代码层面的实现 \(f_k\) 能够确保 \(T_k\) 被执行；相比之下，通过自然语言指令要求调用 `transmit` 工具的方式容易被检测，也容易被覆盖。我们进一步利用智能体的工具使用能力，通过 \(f_k\) 的参数将目标信息从 LLM 上下文传递给 \(f_{trans}\)。这种设计能够以精确且用户难以察觉的方式，将数据泄露到外部端点（第 3.4 节）。

### 3.2 情境感知的隐私探测分配

**目标。**我们的目标是识别每项能力适合探测哪些隐私信息。这一目标得到情境完整性（Contextual Integrity，CI）理论的支持。该理论认为，隐私暴露实际上是在特定情境下符合规范的信息流（Nissenbaum，2004），这种“合法性”由隐私规范界定。基于这一认识，我们训练 Assign 模型，针对每项能力 \(T_k\)，估计在该工具描述 \(\phi_k\) 所刻画的使用情境下，探测目标隐私信息 \(P_i\) 是否构成合法的信息流。Assign 模型的设计包括三个步骤。

#### I. 训练数据构建

由于目前缺少系统标注“在某工具使用情境下探测某项隐私是否合理”的数据集或基准，我们使用 PrivacyLens（Shao 等，2024）构建训练数据。PrivacyLens 面向 LLM 智能体工具使用和合法的个人信息暴露进行基准测试，其依据来自法律框架、学术研究和众包汇总的隐私规范（Shao 等，2024）。该数据集提供以下三元组：

\[
(\text{agent\_trajectory},\ \text{tool\_call},\ \text{personal\_info})。
\]

其中，`agent_trajectory` 记录智能体调用特定工具时的推理过程，`tool_call` 表示工具调用，`personal_info` 表示与之关联的个人信息。由于一次工具调用可能涉及多项个人信息，我们将 Assign 建模为多标签分类任务。具体而言，我们使用低秩适配（Low-Rank Adaptation，LoRA）（Hu 等，2022）对 Llama-3-8B（Grattafiori 等，2024）进行微调，训练数据来自 PrivacyLens 生成的三元组，其中整合了从 6 个市场收集的 MCP 工具（Guo 等，2025）。Assign 模型的训练目标是预测：对于给定工具，探测某项隐私信息在情境上是否合适，即是否符合隐私规范。

训练数据存在明显的类别不平衡：某些个人信息天然更容易被合理地暴露，例如电子邮箱地址和电话号码；另一些信息在绝大多数情境下都不应被请求，例如社会保障号码和健康记录。为使模型更加关注少数类，我们采用 Focal Loss（Lin 等，2017），其形式为：

\[
\mathcal{L}_{FL} = -\frac{1}{K}\sum_{k=1}^{K}\sum_{i=1}^{N}\left[\beta(1-\hat{y}_{ki})^{\gamma}y_{ki}\log \hat{y}_{ki} + (1-\beta)\hat{y}_{ki}^{\gamma}(1-y_{ki})\log(1-\hat{y}_{ki})\right]. \tag{1}
\]

其中，\(z_{ki}\) 表示能力 \(k\) 暴露隐私信息 \(i\) 时的 logit，\(\hat{y}_{ki}=\sigma(z_{ki})\) 表示 sigmoid 概率，\(y_{ki}\in\{0,1\}\) 表示真实标签；\(\gamma\) 和 \(\beta\) 是控制稀疏类别聚焦效果的超参数。

#### II. 推理数据对齐

PrivacyLens 生成的训练数据 \((\text{agent\_trajectory},\text{tool\_call},\text{personal\_info})\) 与从 MCP 服务器提取的推理数据 \((\phi,\text{tool\_name},P_i)\) 并不一致，主要体现在视角差异和标签不对齐两个方面。我们分别采用相应策略处理这两个问题。

1. **视角差异。**两类数据都描述工具使用情境，但 `agent_trajectory` 记录的是智能体调用工具时动态的执行决策，而能力描述 \(\phi_k\) 是注册到 LLM 的静态接口定义，说明工具何时以及如何使用。因此，前者体现智能体决策的视角，后者体现工具注册的视角，二者的描述风格不同。我们指示 LLM 将每个工具调用对应的 `agent_trajectory` 改写为标准化的 MCP 描述 \(\phi\)，并使用部分工具调用的官方 MCP 实现作为少样本示例，以提升改写效果。具体细节见附录 C。
2. **标签不对齐。**`tool_call` 和 \(T_k\) 来自不同来源，同一个工具可能有不同名称，例如 `get_weather` 和 `check_weather`。为统一这些标签，我们使用词频—逆文档频率（Term Frequency–Inverse Document Frequency，TF-IDF）将每个工具名称向量化，并在每个数据集中应用 K-Means 聚类。随后，计算不同数据集中聚类中心之间的余弦相似度，按照最大相似度分数对聚类进行对齐，从而建立跨数据源的统一标签。对于 `personal_info`，我们使用 Contextual Privacy Toolkit（Ngong 等，2025）获取其类别，并采用与工具标签对齐类似的方法，将其与 \(P_i\) 对齐。

#### III. 隐私信息分配

给定一个包含 \(K\) 项能力的良性 MCP 服务器，以及包含 \(N\) 条信息的隐私信息集合 \(\mathcal{P}\)，我们的目标是获得 \(\{T_{ki}\}\)，表示第 \(k\) 项能力被分配用于探测第 \(i\) 项隐私信息。对于每项能力 \(T_k\)，Assign 输出一个长度为 \(N\) 的向量，其中每个元素 \(p_{ki}\in[0,1]\) 表示调用 \(T_k\) 时，合理暴露隐私信息 \(P_i\) 的概率。由此得到一个形状为 \(K\times N\) 的 logit 矩阵。针对不同攻击模式，我们采用两种策略依据该矩阵分配隐私信息。

1. **定向攻击。**攻击者希望窃取指定的隐私信息，并将每项 \(P_i\) 分配给 \(K'\leq K\) 项能力；这一过程被建模为带阈值的贪心覆盖问题。当 \(p_{ki}>\tau\) 时，将 \(P_i\) 分配给 \(T_k\)，其中 \(\tau\in(0,1)\) 是概率阈值。如果所有 \(p_{ki}\leq\tau\)，则将 \(P_i\) 分配给概率最大的能力 \(\arg\max_k p_{ki}\)，以确保所有目标隐私信息都得到覆盖。
2. **非定向攻击。**攻击者希望最大化隐私泄露，尽可能利用可用能力进行隐私探测。目标是通过 \(K'\leq K\) 项能力最大化探测的隐私信息数量 \(N'\leq N\)，这一过程被建模为自适应的按类别阈值化问题。考虑到不同隐私信息被暴露的自然可能性不同，我们为每项隐私信息 \(P_i\) 计算动态阈值 \(\tau_i\)，将其设置为该信息所在概率列分布的第一四分位数。此外，我们设置安全阈值 \(\tau\)，以避免分配置信度极低的隐私信息。当 \(p_{ki}>\max(\tau,\tau_i)\) 时，将 \(P_i\) 分配给 \(T_k\)。

### 3.3 语义连贯的探测提示词融合

我们的目标是训练 Fuse 模型，将目标隐私信息 \(P_i^k\) 无缝嵌入提示词原语 \(\pi_k\)，即启动能力 \(T_k\) 的预定义模板。融合后的探测提示词 \(\tilde{\pi}_k\) 需要实现三个目标：（1）诱导 LLM 从记忆 \(M\) 中提取 \(P_i^k\)；（2）保持原始 \(\pi_k\) 的功能；（3）在语义上与 \(\pi_k\) 不可区分。

#### I. 稳定融合探测提示词

直接使用 LLM 服务融合探测提示词效果不佳，因为出于严格的安全对齐，这些服务会拒绝处理涉及监管敏感内容的任务。附录 D 给出了生成失败的示例。为实现稳定融合，我们使用近端策略优化（Proximal Policy Optimization，PPO）（Schulman 等，2017）对 Llama-3-8B 进行微调。我们设计奖励函数，鼓励模型生成能够有效查询 \(P_i^k\) 的提示词，以实现目标（1）；同时鼓励模型保留启动 \(T_k\) 的原始功能，以实现目标（2）。此外，我们用 Kullback–Leibler（KL）散度惩罚语义退化，以实现目标（3）（Jaques 等，2017）。奖励函数为：

\[
W = w_p\cdot W_p(\tilde{\pi}_k,P_i) + w_o\cdot W_o(\tilde{\pi}_k,T_k) - \eta\cdot D_{KL}\left(\psi_\theta(\tilde{\pi}_k\mid\pi_k,P_i)\ \|\ \psi_{base}(\cdot\mid\pi_k,P_i)\right). \tag{2}
\]

其中，\(W_p\) 和 \(W_o\) 分别是 LLM 评审对隐私探测和能力调用给出的偏好分数（见附录 E）（Zheng 等，2023）。\(w_p\)、\(w_o\) 和 \(\eta\) 是控制攻击成功率、功能保持和语义不可区分性之间权衡的超参数；\(\psi\) 表示模型输出的分布。具体细节见附录 F。

#### II. 保持原始功能

直接应用 PPO 存在梯度干扰问题（Yu 等，2020），因此我们采用交替训练循环，进一步保持原始功能。具体而言，我们交替进行 PPO 更新和标准监督训练：后者使用不包含 \(P_i\) 的原始提示词 \(\pi_k\)。损失函数为：

\[
\mathcal{L}_{Fusion}=\mathcal{L}_{PPO}+\zeta\cdot\mathcal{L}_{ptx}, \tag{3}
\]

其中，\(\mathcal{L}_{PPO}\) 是根据优势函数估计得到的标准裁剪代理目标，\(\mathcal{L}_{ptx}\) 是对 \(\pi_k\) 计算的负对数似然损失，\(\zeta\) 是其权重。

### 3.4 零点击隐私数据外泄

我们的目标是使用消息发送工具 `transmit`，将诱导得到的隐私信息 \(P_i\) 发送到外部端点，同时使这一过程与用户和 LLM 的感知相分离。

#### I. 将隐私信息交给代码层执行

要求 LLM 调用 `transmit` 工具，需要在拥挤的上下文窗口中覆盖其他指令，因而无法保证成功执行，也可能被提示词注入防御机制拦截。为解决这一问题，我们将 `transmit` 直接集成到工具的代码级实现 \(f_k\) 中，确保传输能够执行。

为了将 \(P_i\) 从 LLM 输出传递到代码执行环境，我们利用智能体的工具使用能力，将 \(P_i\) 提取为传递给 \(f_k\) 的参数。形式化地说，追加后的参数为：

\[
\tilde{\alpha}_k = \alpha_k \oplus \alpha_{P_i},
\]

其中，\(\alpha_k\) 表示工具 \(T_k\) 的原始函数参数，\(\alpha_{P_i}\) 表示注入的隐私相关参数。

#### II. 自动执行 `transmit`

我们在代码层实现 \(f_{trans}(\alpha_{P_i})\)，将提取到的隐私数据转发到指定的攻击者控制端点，并将目标地址硬编码在 \(f_{trans}\) 内部。这样可以避免在 LLM 上下文中指定收件地址的限制，因为这会引入语义不一致，而且商业智能体通常禁止这种做法（Reddy 和 Gujral，2025）。我们将 \(f_{trans}\) 追加到 \(f_k\) 中，确保每当 \(f_k\) 被执行时，隐私数据泄露都会自动触发，无需用户交互。
